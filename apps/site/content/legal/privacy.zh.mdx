本政策适用于 PiNomad 作者运营的官方服务端 `app.pinomad.si`，以及本网站 `pinomad.si`。PiNomad 是开源软件，任何人都可以自己架服务端。如果你用的是别人运营的服务端（包括你自己架的），由那个服务端的运营者负责，本政策不适用。

## 简要说明

- Agent 跑在你自己的机器（宿主）上。对话、文件和命令在你的设备和宿主之间端到端加密传输，服务端转发的只是密文，读不到内容。
- 服务端存你的账号（邮箱、设了密码时的密码哈希，以及你绑定的 Google、GitHub 或 Apple 登录）、账号下的宿主、登录会话、你登录过的设备和它们加入过哪些宿主，以及 iPhone App 的推送登记。
- 邮箱只用来登录、给你发验证码，以及告诉你账号安全方面的变化。不发营销邮件，没有统计分析和广告，不出售任何数据，除了"处理部分数据的服务"里列出的服务，也不共享给别人。
- 删除账号时，服务端上关于它的记录一并删除，服务端还会请 Apple 撤销 PiNomad 对你 Apple ID 的授权。

## 服务端存什么

以下内容都存在服务端的一个数据库里。

- **账号**：邮箱和验证时间、密码的 scrypt 哈希（从不存密码本身；只用 Google、GitHub 或 Apple 登录的账号没有密码）、一个随机的账号 ID（你的 App 用它在同一台设备上区分不同账号的配对），以及账号创建时间。邮箱注册上线之前建的账号，在补上邮箱之前保留原来的用户名。
- **登录方式**：你绑定的每个 Google、GitHub 或 Apple 登录：哪个提供方、它给你的 ID（一串数字或不透明的字符串，不是你在那边的邮箱或用户名）、它报告的邮箱，以及绑定时间。Apple 还有你第一次登录时选择分享的姓名（如果有），以及 Apple 签发的一个 token；服务端存它只是为了在你解绑 Apple 或删除账号时撤销 PiNomad 的授权。
- **邮件验证码**：服务端发给你的每个验证码（注册、重置密码、添加邮箱或确认操作）：验证码的哈希、用途、邮箱、所属账号（如果已经有账号）、输错过几次，以及过期时间。
- **进行中的 Google、GitHub、Apple 登录**：你在提供方页面上时，把它的回复和你的浏览器或 App 对上的状态。回来时如果没有匹配的账号，服务端还会暂存提供方报告的内容（ID、邮箱，Apple 还有姓名和 token），等你选择新建账号或绑定到已有账号。这些步骤里由你的浏览器或 App 持有的密钥，服务端只存 SHA-256 哈希。
- **二次确认**：你用密码或邮件验证码确认某个操作时，服务端给这个会话的短期确认凭据的哈希。
- **登录会话**：每个登录的浏览器或 App 一条：会话令牌的 SHA-256 哈希、签发时间和过期时间。
- **账号下的宿主**：每台用 `pinomad join` 加入的宿主：它的 ID、公钥（用来建立加密通道）、显示名称（默认是机器的主机名）、加入时间和最近一次连上的时间。
- **账号下的设备**：每个登录过的浏览器或 App 一条：App 在那台设备上随机生成的 ID（不是从硬件推导出来的）、App 给自己起的名字（比如"Mac Chrome""Mac Desktop""iPhone"）、首次和最近一次登录的时间，以及如果你移除过它，移除的时间。服务端用它列出你的设备，并把某台设备从宿主上移除。
- **设备在宿主上的记录**：设备通过账号和宿主配对时，是哪台设备要的、哪台宿主、宿主的邀请什么时候过期。宿主接纳这台设备后，会报告它登记的公钥，服务端保留这把公钥，以便之后请宿主吊销它。你移除一台设备后，服务端还会保留宿主还没确认的吊销请求。
- **加入宿主的命令**：**Add a host** 给出的一次性命令，存为 SHA-256 哈希，连同生成它的账号、生成时间、过期时间和使用时间。
- **等待加入的宿主**：不带令牌运行 `pinomad join` 时，这台宿主的 ID、名称、系统（比如"macOS (arm64)"）和它发起请求时的 IP 地址，让你输入短码的页面能告诉你加入的是哪台机器。两个码都存为 SHA-256 哈希。名称、系统和 IP 地址在你确认或拒绝这个请求时立即删除，最晚在请求 10 分钟后过期时删除。
- **推送登记**：打开了推送的 iPhone：Apple 发给 App 的设备 token、是正式版还是开发版构建、属于哪个账号、是账号下哪台设备登记的，以及 App 最近一次刷新的时间。服务端用它核对宿主只能给登录在同一个账号下的设备发通知。

## 服务端看不到什么

- **你的工作内容。** 提示词、模型回复、文件、工具调用、终端输出和你的模型服务商登录信息都只在宿主和你的设备上。它们之间的一切都走端到端加密通道（Noise）。设备直连不上宿主时，服务端转发这条通道的密文，不保留任何一份。
- **通知内容。** 推送通知只带对话标题和事件（等你回答、完成、失败），不带问题和回复。标题会经过服务端和 Apple 的推送服务送到手机上，服务端不保存。
- **配对细节。** 通过账号给设备配对时，服务端把宿主的一次性邀请和它的网络地址转给你的设备，邀请和地址都不保留（只留下"设备在宿主上的记录"里说的那条记录）。

## 经过但不保留的

- **IP 地址和邮箱。** 和任何服务器一样，它能看到每条连接的地址。它在内存里按 IP 地址限制登录、注册、验证码和宿主加入的尝试次数，按邮箱限制发往同一个地址的验证码数量，这些计数最多保留一小时，服务端重启就没了。地址不写进服务端自己的日志；数据库里只有等待加入的宿主的 IP 地址（见上）。
- **日志。** 服务端日志记录启动；每次推送的宿主 ID、构建类型、结果和耗时；以及失败：发不出去的邮件（只记用途，不记地址和验证码）、失败的 Google、GitHub、Apple 登录（提供方和错误），以及失败的 Apple 撤销。不记通知内容、推送 token、密码、验证码和连接。日志只留在服务端上，由系统轮转清理。

## 服务端发的邮件

只有这几种，都发到账号的邮箱（注册时发到你填的邮箱）：

- 验证码：注册、重置密码、添加邮箱，或者确认删除账号这类操作。
- 有人用已有账号的邮箱注册时：一封说明这个邮箱已有账号的信，不发验证码。
- Google、GitHub 或 Apple 因为报告了同一个已验证邮箱而自动绑定到你的账号时的通知；账号邮箱改了时，发到旧邮箱的通知。

## 处理部分数据的服务

- **发信：** 官方服务端经 Resend 发信，Resend 能看到收件地址和邮件内容（包括验证码）。
- **Google、GitHub 和 Apple：** 只在你用它们登录时。提供方知道你登录了 PiNomad。服务端向它要你的邮箱和你在那边的 ID（Google 和 GitHub 还会给出基本资料，Apple 给出你选择分享的姓名），只保存 ID、邮箱，以及 Apple 的那个姓名。
- **Apple 推送服务：** 见"服务端看不到什么"和"数据存放在哪里"。

## 服务端可以为新设备担保

在新设备上登录、通过账号和宿主配对时，宿主接受这台设备，是因为服务端为它担保。所以服务端的运营者是你需要信任的一方：

- 运营服务端的人，或者攻破了服务端的人，可以给你账号下的宿主加一台设备。这台设备和你的设备有同样的权限，包括宿主上的 shell。
- 他们也可以在一台设备第一次配对时给出假的宿主公钥，读到这台设备的流量。
- 已经配对的设备不受影响；你在宿主上吊销的设备会一直保持吊销。

不想给出这份信任，可以在宿主的设备设置里关掉 **Accept devices from your account**，只用扫码配对；或者自己架服务端。这个设计的理由见 [ADR-0022](https://github.com/bubbleptr/pinomad/blob/main/docs/adr/0022-server-accounts-and-vouching.md)。

## 保留多久

- **账号**：直到你删除它。
- **登录方式**：直到你解绑或删除账号。最后一种登录方式不能解绑。
- **邮件验证码**：10 分钟，或者用掉为止；输错五次作废。过期的一分钟内清掉。
- **进行中的提供方登录**：最多 10 分钟，包括等你选择怎么处理时暂存的提供方信息；App 用来换会话的一次性 code 只有 2 分钟。过期后一分钟内清掉。
- **二次确认**：5 分钟，或者拿到它的会话结束为止。
- **宿主**：直到你在宿主上运行 `pinomad leave`、把它加入另一个账号，或者删除账号。
- **会话**：登录后 30 天，不续期。退出登录删掉这一条；**Sign out everywhere** 删掉全部；改密码删掉除当前这条以外的全部。
- **账号下的设备**：直到你删除账号。移除的设备仍在列表里，标为已移除。旧版 App 留下的无名记录，没有会话、也没有宿主记录时，会在之后的某次登录时清掉。
- **设备在宿主上的记录**：宿主一直没报告的配对，在邀请过期一天后清掉。其余的保留到宿主退出你的账号（`pinomad leave`）、加入另一个账号，或者你删除账号。待处理的吊销请求在宿主确认后删除。
- **加入宿主的命令**：10 分钟后过期，下次有人生成新命令时清掉过期的。
- **等待加入的宿主**：宿主的名称、系统和 IP 地址在你确认或拒绝时删除，其余部分在宿主拿到结果后删除。没人处理的请求 10 分钟后过期，之后一分钟内清掉。
- **推送登记**：在手机上关掉推送或退出登录、在 **Devices** 里移除这台手机、使用 **Sign out everywhere**、改密码、删除账号，或者 Apple 报告 token 失效时删除。App 90 天没有刷新的登记视为无效，之后清掉。每个账号最多保留 32 条。
- **限速计数**（登录、注册、验证码、宿主加入）：最多一小时，只在内存里。

## 删除账号

你可以随时删除自己的账号，服务端会先要你输入密码；没有密码的账号改为输入发到邮箱的验证码。如果你用的 App 还没有这个选项，请联系我们（见"联系"）。

删除账号会一次删掉：账号和邮箱、它的登录方式、会话、设备和这些设备在宿主上的记录、加入宿主的命令、宿主绑定、邮件验证码和推送登记。绑定过 Apple 的，服务端会请 Apple 撤销 PiNomad 的授权；撤销失败不影响删除，只记进日志。账号下的宿主会立刻和服务端断开，把它们加入另一个账号之前，不能再经服务端连接。

不会动的：每台宿主上的已配对设备列表。设备列表由每台宿主自己保管，谁能进来由宿主决定，所以这些设备在宿主上仍然保持配对，直到你在宿主的设备页面里吊销。想让宿主先吊销某台设备，在删除账号之前到账号面板的 **Devices** 里移除它。宿主上的其他东西都是你的，从来不在服务端上。

## 本网站

`pinomad.si` 是由 Cloudflare Pages 提供的静态页面，Cloudflare 处理每个请求，能看到 IP 地址、浏览器等常规请求信息。网站没有统计分析，不从其他网站加载任何东西，字体也由本站提供。

- `app.pinomad.si` 上的 Web 端会在用过它的浏览器里给 `pinomad.si` 设一个 cookie：`pinomad_app=1`。它不含任何账号信息，只是让网站的 **登录** 链接变成 **打开 Web 端**，并让首页直接跳到 Web 端。
- 文档页把你选的浅色或深色主题记在浏览器的本地存储里。
- Web 端本身用一个脚本读不到的会话 cookie 保持登录，并把已配对的宿主和登录时发送的随机设备 ID 存在浏览器的本地存储里。用 Google、GitHub 或 Apple 登录时，还会设一个脚本读不到的 cookie，把提供方的回复和你的浏览器对上，10 分钟后失效。

## 数据存放在哪里

服务端运行在美国洛杉矶的一台虚拟服务器上。推送通知经过 Apple 的推送服务，那部分适用 Apple 自己的隐私政策。
