This policy covers the official PiNomad server at `app.pinomad.si`, run by PiNomad's author, and this website, `pinomad.si`. PiNomad is open source and anyone can run their own server. If you use a server someone else runs, including one you run yourself, its operator is responsible for it and this policy doesn't apply.

## In short

- Your agent runs on your own machine (the host). Conversations, files and commands travel between your devices and your host end-to-end encrypted. The server forwards them as ciphertext and can't read them.
- The server stores your account (a username and a password hash), the hosts on your account, your sign-in sessions, and push registrations from the iPhone app.
- No email address, no real name, no analytics, no ads. Nothing is sold or shared.
- When you delete your account, the server's records of it go with it.

## What the server stores

All of this lives in one database on the server.

- **Account:** your username, your password as a scrypt hash (never the password itself), when the account was created, and whether it is the admin account.
- **Sign-in sessions:** one for each browser or app you sign in on: a SHA-256 hash of the session token, when it was issued and when it expires.
- **Hosts on your account:** for each host you join with `pinomad join`: its ID, its public key (used to set up the encrypted channel), its display name (by default the machine's hostname), when it joined and when it last connected.
- **Host join commands:** the one-time command from **Add a host**, stored as a SHA-256 hash with the account that made it, when it was made, when it expires and when it was used.
- **Push registrations:** for an iPhone with push turned on: the device token Apple gave the app, whether it's a production or development build, the account it belongs to, and when the app last refreshed it. The server uses this to check that a host only sends notifications to devices signed in to the same account.
- **Invites:** a SHA-256 hash of each invite code, who created it, when it was created and expires, and when it was used and by which account.

## What the server can't see

- **Your work.** Prompts, model replies, files, tool calls, terminal output and your model provider sign-ins stay on your host and your devices. Between them, everything goes over an end-to-end encrypted channel (Noise). When a device can't reach your host directly, the server forwards that channel's ciphertext and keeps none of it.
- **Notification content.** A push notification carries only the conversation title and the event (waiting for your answer, finished, failed), never the question or the reply. The title passes through the server and Apple's push service on its way to your phone. The server doesn't store it.
- **Pairing details.** When you pair a device through your account, the server passes the host's one-time invite and its network addresses to your device and doesn't keep them.

## What passes through without being kept

- **IP addresses.** Like any server, it sees the address of each connection. It keeps addresses in memory to limit sign-in and sign-up attempts; those counters last a few minutes and are gone when the server restarts. Addresses aren't written to the database or to the server's own log.
- **Logs.** The server's log records when it starts and, for each push notification, the host ID, the build type, the result and how long it took. It doesn't log notification content, push tokens, passwords, usernames or connections. Logs stay on the server and are rotated by the system.

## The server can vouch for new devices

When you sign in on a new device and pair it with a host through your account, the host accepts the device because the server vouches for it. That makes the server operator a trusted party:

- Whoever runs the server, or anyone who breaks into it, could add a device to a host on your account. That device would have the same access as yours, which includes a shell on the host.
- They could also give a device that is pairing for the first time a fake host key and read that device's traffic.
- Devices that are already paired aren't affected, and a device you revoke on a host stays revoked.

If you don't want to extend that trust, turn off **Accept devices from your account** in the host's Devices settings, so that only QR-code pairing works, or run your own server. The reasoning behind this design is in [ADR-0022](https://github.com/bubbleptr/pinomad/blob/main/docs/adr/0022-server-accounts-and-vouching.md) (in Chinese).

## How long things are kept

- **Account:** until you delete it.
- **Hosts:** until you run `pinomad leave` on the host, join it to another account, or delete your account.
- **Sessions:** 30 days from sign-in, never extended. Signing out removes that session; **Sign out everywhere** removes all of them; changing your password removes all but the one you're using.
- **Host join commands:** they expire after 10 minutes, and expired ones are cleared the next time anyone makes one.
- **Push registrations:** removed when you turn push off or sign out on the phone, use **Sign out everywhere**, change your password, delete your account, or when Apple reports the token is no longer valid. A registration the app hasn't refreshed for 90 days is ignored and then cleared. An account keeps at most 32.
- **Invites:** an unused invite expires after 7 days and is cleared later. A used invite stays on record as used.
- **Sign-in rate limits:** a few minutes, in memory only.

## Deleting your account

You can delete your account at any time; the server asks for your password first. If your app doesn't offer the option yet, ask the operator (see Contact).

Deleting the account removes, in one step, your account, its sessions, its host join commands, the bindings of your hosts and its push registrations. Your hosts are disconnected from the server right away and can't connect through it again until you join them to another account. Invites you used stay marked as used, without your name.

What it doesn't touch: the list of paired devices on each host. Each host keeps its own list and is the one that decides who gets in, so devices stay paired there until you revoke them in the host's Devices page. Everything else on your hosts is yours and was never on the server.

The admin account can't be deleted this way, because only it can create invites.

## This website

`pinomad.si` is a set of static pages served by Cloudflare Pages, which handles each request and sees the usual request details, such as your IP address and browser. The site has no analytics and loads nothing from other sites; fonts are served from the site itself.

- The web app at `app.pinomad.si` sets one cookie on `pinomad.si`, `pinomad_app=1`, in browsers that have used it. It holds no account information; it only makes the site's **Sign in** link read **Open web app** and send the home page straight to the app.
- The docs remember your light or dark theme in your browser's local storage.
- The web app itself keeps you signed in with a session cookie that scripts can't read, and stores your paired hosts in the browser's local storage.

## Where data is stored

The server runs on a virtual server in Los Angeles, in the United States. Push notifications go through Apple's push service, which Apple runs under its own privacy policy.
