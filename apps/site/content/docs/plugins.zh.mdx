插件是宿主上的一个目录。它可以给 agent 加工具，按对话保存自己的状态，还可以给 Web 和桌面端带来界面：侧边面板里的一页，以及对话记录里它那些工具调用的卡片。

插件界面只在 Web 和桌面端有。iPhone 上插件的工具照常能用，只是看不到它的面板和卡片。

## 安装插件

1. 把插件目录复制到宿主数据目录下的 `plugins/` 里：`~/.pinomad/plugins/<名字>/`；宿主带 `--data-dir` 启动的话，就放到那个目录下。也可以放一个指向别处目录的软链接。
2. 重启宿主：作为服务运行的用 `pinomad service restart`（会先等进行中的任务结束），在终端里跑的就停掉再启动。宿主只在启动时加载插件，所以改了、加了或删了插件都要再重启一次。

加载失败的插件会被跳过，宿主日志里留一行原因，宿主和其他插件照常运行。

**装插件就是信任它。** 插件的宿主侧代码跑在宿主进程里，权限和宿主一样；界面代码和 Web、桌面端跑在同一个页面里，这个页面能读到的它都能读到，包括这台设备连宿主用的密钥。只装你信得过代码的插件。

目前没有插件市场，也不支持从 npm 安装或按项目装插件。

## 写插件

插件目录里是一份清单和最多两个代码文件：

```
artifact/
  plugin.json
  host.ts     跑在宿主上：工具、状态、方法
  web.js      跑在 Web 和桌面端：侧边面板、工具卡片
```

`plugin.json`：

```json
{ "name": "artifact", "api": 1, "host": "host.ts", "web": "web.js" }
```

- `name` 必须和目录名相同：小写字母、数字和 `-`，以字母开头。
- `api` 是插件 API 的版本，现在是 `1`。
- `host` 和 `web` 是目录里的文件名，都可以省略：只有工具的插件不写 `web`，只有界面的插件不写 `host`。

API 的类型定义在 PiNomad 仓库里：宿主侧是 [`packages/plugin/src/v1.ts`](https://github.com/bubbleptr/pinomad/blob/main/packages/plugin/src/v1.ts)，浏览器侧是 [`v1-web.ts`](https://github.com/bubbleptr/pinomad/blob/main/packages/plugin/src/v1-web.ts)，没有发布成 npm 包。只用 `import type` 引入：API 对象是作为参数传给插件的，运行时没有东西要 import。

### 宿主侧

宿主直接用 Node 的类型剥离运行 `host.ts`，所以 TypeScript 里只能用去掉类型就能跑的写法（不能用 `enum`、`namespace`），也可以直接写 JavaScript。它的默认导出是一个函数，接收宿主 API，在插件加载时把东西都注册好：

- `state(name, { version, initial, shared })`：按对话保存的 JSON 状态。`initial()` 是对话还没写过时的值。`shared: false` 的状态只留在宿主上；默认会同步给客户端，界面用 `useState` 读。共享状态会同步到每个正在看这段对话的客户端，所以大块内容放在只留宿主的状态里，界面再通过方法去取。
- `tool({ name, description, parameters, run })`：模型能调用的工具。`parameters` 是 JSON Schema 对象。`run(args, ctx)` 返回 `{ text }`，就是模型看到的结果；抛错的话模型收到一条失败结果，内容是错误信息。工具名只能用字母、数字和 `_`，最长 64 个字符，不能以 `mcp__` 开头，也不能和宿主上已有的工具重名；工具名被占用的插件整个跳过。宿主重启打断的调用不会重跑。
- `method(name, run)`：给界面用 `call` 或 `useCall` 调的函数。`run(args, ctx)` 收发 JSON；抛错的话这次调用失败，带上错误信息。

`ctx` 是这次工具调用或方法调用所属的对话：

- `ctx.conversationId`
- `ctx.read(state)`：已提交的值。
- `ctx.change(async (tx) => { … })`：一次提交。`await tx.get(state)` 拿到一份草稿，直接改它；改过的草稿要么一起存下，要么都不存。

插件状态和对话的其他内容一样跟着对话历史走：Fork 出来的对话从分叉那一刻的状态开始。

### 浏览器侧

`web.js` 是一个 ES 模块，默认导出接收浏览器 API。这个文件由你自己构建，宿主原样提供；客户端先核对它和宿主公布的哈希一致，再运行。React 从 API 里拿，不要自己打包一份，否则 hooks 用不了。

- `React`：App 用的 React。
- `panel({ id, label, component })`：侧边面板里的一页。`label` 是它在对话标题栏里那个按钮的名字。
- `toolCard(toolName, component)`：替换对话记录里这个工具每次调用的详情（展开调用时看到的部分）。组件拿到 `tool`：`name`、`args`（解析好的参数，还在流式传输时是 `undefined`）、`output`（模型看到的结果文本，调用结束后才有）和 `state`。
- `useState(stateName)`：hook，当前显示的对话里这个插件的共享状态，还没收到时是 `undefined`。
- `useCall(method, args, deps)`：hook，方法的返回值，`deps` 变了就重新调用；`args` 传 `undefined` 就不调。
- `call(method, args)`：对当前显示的对话调用一个方法，返回 Promise。
- `openPanel(id)`：打开这个插件的某个面板。
- `Sandbox`：渲染一份 HTML 文档的组件，见下文。

面板和卡片要在默认导出运行时注册，之后再注册会被忽略。插件组件抛错时，它那块位置显示一行提示，App 的其他部分不受影响。

### 沙箱

插件的界面代码是你信任的，模型写出来的内容不是。`Sandbox` 接收 `html`（一份完整的文档）和 `title`（框架的无障碍名称），在一个框架里渲染这份文档，脚本照常运行。它会撑满给它的空间。`html` 一变，就是一份新文档。

沙箱承诺的是：里面的内容碰不到客户端的任何东西，包括设备密钥、存储和 App 页面。它不承诺断网：fetch、跳转和外部的脚本、样式、图片都尽量拦下了，但拦不住 WebRTC，页面仍然可以经 STUN 或 DNS 往外发数据。内联脚本和样式可以用，图片可以用 `data:` URL。

## 示例：artifact

仓库里的 [`examples/plugins/artifact`](https://github.com/bubbleptr/pinomad/tree/main/examples/plugins/artifact) 是一个完整的插件：模型写一个网页，它的工具卡片显示页面标题和 **Open** 按钮，**Artifact** 面板在沙箱里显示这个页面。它没有内置，想试的话把目录复制到 `~/.pinomad/plugins/artifact/`，再重启宿主。

宿主侧把页面留在宿主上，只共享标题和一个版本号：

```ts
import type { HostApi } from "@pinomad/plugin/v1";

export default (pinomad: HostApi): void => {
  const page = pinomad.state("page", { version: 1, shared: false, initial: () => ({ title: "", html: "" }) });
  const current = pinomad.state("current", { version: 1, initial: () => ({ title: "", revision: 0 }) });

  pinomad.tool({
    name: "artifact_write",
    description: "Show a page to the user in the side panel. …",
    parameters: {
      type: "object",
      properties: { title: { type: "string" }, html: { type: "string" } },
      required: ["title", "html"],
    },
    run: async (args, ctx) => {
      const title = String(args.title);
      const html = String(args.html);
      await ctx.change(async (tx) => {
        Object.assign(await tx.get(page), { title, html });
        const shown = await tx.get(current);
        shown.title = title;
        shown.revision += 1;
      });
      return { text: `Showing "${title}" in the side panel.` };
    },
  });

  pinomad.method("read", async (_args, ctx) => ctx.read(page));
};
```

浏览器侧是一个普通的 ES 模块，用 `React.createElement` 代替 JSX，所以不用构建。面板读共享的版本号，版本号一变就重新取页面：

```js
export default function artifact(pinomad) {
  const h = pinomad.React.createElement;

  function Panel() {
    const current = pinomad.useState("current");
    const revision = current === undefined ? 0 : current.revision;
    const page = pinomad.useCall("read", revision > 0 ? null : undefined, [revision]);
    if (revision === 0) return h("p", null, "No artifact yet. Ask the agent to make a page.");
    if (page === undefined) return h("p", null, "Loading…");
    return h("div", { style: { display: "flex", height: "100%" } }, h(pinomad.Sandbox, { title: page.title, html: page.html }));
  }

  function Card({ tool }) {
    return h(
      "div",
      null,
      h("span", null, tool.args?.title ?? "Untitled page"),
      h("button", { type: "button", onClick: () => pinomad.openPanel("page") }, "Open"),
    );
  }

  pinomad.panel({ id: "page", label: "Artifact", component: Panel });
  pinomad.toolCard("artifact_write", Card);
}
```

卡片只显示标题：参数里还有整份文档，不该摊在对话记录里。仓库里的文件多了样式和注释。
