---
title: 插件
description: 给宿主加工具、侧边面板和工具卡片；装插件就是复制一个目录，也可以自己写。
---

插件是宿主上的一个目录。它可以给 agent 加工具，按对话保存自己的状态，还可以给 Web 和桌面端带来界面：侧边面板里的一页，以及对话记录里它那些工具调用的卡片。

插件界面只在 Web 和桌面端有。iPhone 上插件的工具照常能用，只是看不到它的面板和卡片。

## 安装插件

把插件目录复制到宿主数据目录下的 `plugins/` 里：`~/.pinomad/plugins/<名字>/`；宿主带 `--data-dir` 启动的话，就放到那个目录下。也可以放一个指向别处目录的软链接。

运行中的宿主会发现新目录并加载插件，不用重启。之后它也盯着插件的文件：改了文件，agent 的下一次工具调用就跑新代码；删掉目录，插件的工具也随之消失。已经在跑的调用用它开始时的代码跑完。

已经打开的 Web 和桌面端会跟着更新，不用重新连接：改过的面板或工具卡片就地换成新版，新加的插件的面板会出现、带着它的状态，删掉的插件的面板和卡片随之消失。只有改过的那个插件的面板会从头显示，其他插件的面板保持原样。把某个状态改成共享或只留在宿主上，已打开的应用里也随之生效。iPhone 上插件的工具同样跟着修改更新。应用版本比宿主旧时，可能要刷新页面才看得到改动。

构建或加载失败的插件会被跳过，宿主日志里留一行原因，宿主和其他插件照常运行。已加载的插件被某次修改改坏时，宿主记下原因，继续用原来的版本，直到后面的修改又能构建通过；已打开的应用也继续显示原来的版本。新的 `web.tsx` 构建通过、但在浏览器里运行出错时，应用在控制台记下错误，继续用原来的版本。

**装插件就是信任它。** 插件的服务端代码跑在宿主进程里，权限和宿主一样；界面代码和 Web、桌面端跑在同一个页面里，这个页面能读到的它都能读到，包括这台设备连宿主用的密钥。只装你信得过代码的插件。

目前没有插件市场，也不支持从 npm 安装或按项目装插件。

## 写插件

插件目录里是一个 `package.json` 和最多两个代码文件：

```
artifact/
  package.json
  server.ts   跑在宿主上：工具、状态、方法
  web.tsx     跑在 Web 和桌面端：侧边面板、工具卡片
```

`package.json`：

```json
{ "name": "artifact", "private": true, "type": "module" }
```

- `name` 是插件名：小写字母、数字和 `-`，以字母开头。目录也用同一个名字。
- `server` 和 `web` 的扩展名可以是 `.ts`、`.tsx`、`.js` 或 `.mjs`。两个都可以省略：只有工具的插件没有 `web.tsx`，只有界面的插件没有 `server.ts`。

两个文件都由宿主用 esbuild 构建，所以 TypeScript、JSX 随便写，也可以把代码拆到目录里的其他文件，互相 import 的部分会一起打包。

API 的类型定义在 PiNomad 仓库里：服务端是 [`packages/plugin/src/v1.ts`](https://github.com/bubbleptr/pinomad/blob/main/packages/plugin/src/v1.ts)，浏览器侧是 [`v1-web.ts`](https://github.com/bubbleptr/pinomad/blob/main/packages/plugin/src/v1-web.ts)，没有发布成 npm 包。插件只从 `@pinomad/plugin/v1` 和 `@pinomad/plugin/v1/web` 引入，运行插件时由宿主提供。

### 从 plugin.json 迁移

宿主自己构建之前写的插件带 `plugin.json` 和 `host.ts`。宿主不再读 `plugin.json`，遇到这样的目录会在日志里留一行。迁移步骤：

1. 按上面的样子加一个 `package.json`，写上插件名。
2. 把 `host.ts` 改名为 `server.ts`，引入 `definePlugin`，用它包住默认导出（见下文）。
3. 删掉 `plugin.json`。手写的 `web.js` 原样能用；想写 JSX 就改名为 `web.tsx`。

### 服务端

`server.ts` 默认导出 `definePlugin(fn)`。`fn` 接收宿主 API，在返回之前把东西都注册好，中间不能 await：

```ts
import { definePlugin } from "@pinomad/plugin/v1";

export default definePlugin((pinomad) => {
  // pinomad.state(…)、pinomad.tool(…)、pinomad.method(…)
});
```

- `state(name, { version, initial, shared })`：按对话保存的 JSON 状态。`initial()` 是对话还没写过时的值。`shared: false` 的状态只留在宿主上；默认会同步给客户端，界面用 `useState` 读。共享状态会同步到每个正在看这段对话的客户端，所以大块内容放在只留宿主的状态里，界面再通过方法去取。
- `tool({ name, description, parameters, run })`：模型能调用的工具。`parameters` 是 JSON Schema 对象。`run(args, ctx)` 返回 `{ text }`，就是模型看到的结果；抛错的话模型收到一条失败结果，内容是错误信息。工具名只能用字母、数字和 `_`，最长 64 个字符，不能以 `mcp__` 开头，也不能和宿主上已有的工具重名。占用内置工具名的插件不会加载，修改后才占用的则继续用原来的版本；两个插件的工具重名时，按字母顺序靠后的那个被跳过。宿主重启打断的调用不会重跑。
- `method(name, run)`：给界面用 `call` 或 `useCall` 调的函数。`run(args, ctx)` 收发 JSON；抛错的话这次调用失败，带上错误信息。

`ctx` 是这次工具调用或方法调用所属的对话：

- `ctx.conversationId`
- `ctx.read(state)`：已提交的值。
- `ctx.change(async (tx) => { … })`：一次提交。`await tx.get(state)` 拿到一份草稿，直接改它；改过的草稿要么一起存下，要么都不存。

插件状态和对话的其他内容一样跟着对话历史走：Fork 出来的对话从分叉那一刻的状态开始。

### 浏览器侧

`web.tsx` 默认导出一个函数，接收浏览器 API。宿主把它构建成一个脚本；客户端先核对脚本和宿主公布的哈希一致，再运行。JSX 用 App 的 React 渲染；`import { useState } from "react"` 拿到的也是这同一份 React，所以从 `react` 还是从 `pinomad.React` 取 hooks，用的都是 App 自己那份。`react-dom` 等其他 React 包不可用。暂时不支持 import CSS 和图片，用内联样式和 `data:` URL。

- `React`：App 用的 React。
- `panel({ id, label, component })`：侧边面板里的一页。`label` 是它在对话标题栏里那个按钮的名字。
- `toolCard(toolName, component)`：替换对话记录里这个工具每次调用的详情（展开调用时看到的部分）。组件拿到 `tool`：`name`、`args`（解析好的参数，还在流式传输时是 `undefined`）、`output`（模型看到的结果文本，调用结束后才有）和 `state`。
- `useState(stateName)`：hook，当前显示的对话里这个插件的共享状态，还没收到时是 `undefined`。
- `useCall(method, args, deps)`：hook，方法的返回值，`deps` 变了就重新调用；`args` 传 `undefined` 就不调。
- `call(method, args)`：对当前显示的对话调用一个方法，返回 Promise。
- `openPanel(id)`：打开这个插件的某个面板。
- `Sandbox`：渲染一份 HTML 文档的组件，见下文。

面板和卡片要在默认导出运行时注册，之后再注册会被忽略。插件组件抛错时，它那块位置显示一行提示，App 的其他部分不受影响。

### 沙箱

插件的界面代码是你信任的，模型写出来的内容不是。`Sandbox` 接收 `html`（一份完整的文档）和 `title`（框架的无障碍名称），在一个框架里渲染这份文档，脚本照常运行。它会撑满给它的空间。`html` 一变，就是一份新文档。

沙箱承诺的是：里面的内容碰不到客户端的任何东西，包括设备密钥、存储和 App 页面。它不承诺断网：fetch、跳转和外部的脚本、样式、图片都尽量拦下了，但拦不住 WebRTC，页面仍然可以经 STUN 或 DNS 往外发数据。内联脚本和样式可以用，图片可以用 `data:` URL。

## 示例：artifact

仓库里的 [`examples/plugins/artifact`](https://github.com/bubbleptr/pinomad/tree/main/examples/plugins/artifact) 是一个完整的插件：模型写一个网页，它的工具卡片显示页面标题和 **Open** 按钮，**Artifact** 面板在沙箱里显示这个页面。它没有内置，想试的话把目录复制到 `~/.pinomad/plugins/artifact/`。

服务端把页面留在宿主上，只共享标题和一个版本号：

```ts
import { definePlugin } from "@pinomad/plugin/v1";

export default definePlugin((pinomad) => {
  const page = pinomad.state("page", { version: 1, shared: false, initial: () => ({ title: "", html: "" }) });
  const current = pinomad.state("current", { version: 1, initial: () => ({ title: "", revision: 0 }) });

  pinomad.tool({
    name: "artifact_write",
    description: "Show a page to the user in the side panel. …",
    parameters: {
      type: "object",
      properties: { title: { type: "string" }, html: { type: "string" } },
      required: ["title", "html"],
    },
    run: async (args, ctx) => {
      const title = String(args.title);
      const html = String(args.html);
      await ctx.change(async (tx) => {
        Object.assign(await tx.get(page), { title, html });
        const shown = await tx.get(current);
        shown.title = title;
        shown.revision += 1;
      });
      return { text: `Showing "${title}" in the side panel.` };
    },
  });

  pinomad.method("read", async (_args, ctx) => ctx.read(page));
});
```

浏览器侧读共享的版本号，版本号一变就重新取页面：

```tsx
import type { PluginToolCall, WebApi } from "@pinomad/plugin/v1/web";

export default function artifact(pinomad: WebApi): void {
  function Panel() {
    const current = pinomad.useState<{ title: string; revision: number }>("current");
    const revision = current === undefined ? 0 : current.revision;
    const page = pinomad.useCall<{ title: string; html: string }>("read", revision > 0 ? null : undefined, [revision]);
    if (revision === 0) return <p>No artifact yet. Ask the agent to make a page.</p>;
    if (page === undefined) return <p>Loading…</p>;
    return (
      <div style={{ display: "flex", height: "100%" }}>
        <pinomad.Sandbox title={page.title} html={page.html} />
      </div>
    );
  }

  function Card({ tool }: { tool: PluginToolCall }) {
    const args = tool.args as { title?: string } | undefined;
    return (
      <div>
        <span>{args?.title ?? "Untitled page"}</span>
        <button type="button" onClick={() => pinomad.openPanel("page")}>Open</button>
      </div>
    );
  }

  pinomad.panel({ id: "page", label: "Artifact", component: Panel });
  pinomad.toolCard("artifact_write", Card);
}
```

卡片只显示标题：参数里还有整份文档，不该摊在对话记录里。仓库里的文件多了样式和注释。
