账号在官方服务端 `https://app.pinomad.si` 上。它替你的设备担保，设备直连不上宿主时转发密文；对话在设备和宿主之间端到端加密。怎么开始用见[快速上手](/zh/docs/)。

## 注册和登录

注册要邀请码：先拿到一个邀请码，再在 [app.pinomad.si](https://app.pinomad.si/) 或 Mac App 的登录表单里点 **Create an account**。

- 用户名只能用小写字母、数字和 `. _ -`，2–32 位。
- 密码至少 12 位。
- 邀请码只能用一次，7 天后过期；用过或过期了，找人再要一个。

Mac App 在还没连上宿主时，首页就是登录表单；之后点侧栏底部的 **Sign in**。**Server** 一栏已经填好 `https://app.pinomad.si`；自己架了服务端的话，填它的地址（见[不用账号](/zh/docs/without-account/)）。

## 账号下的宿主

`pinomad up` 在你确认短码之后把宿主加进账号，见[快速上手](/zh/docs/)。在已经加入的宿主上再跑一次，不用重新输短码，也会留在原来的服务端上；`pinomad status` 能看到加入的是哪个账号。

给脚本用、或者没人能确认短码的机器：**Add a host** 里有 **Advanced: join with a one-time token**，给出一条 `pinomad join https://app.pinomad.si <token>` 命令，不用短码就能加入。拿到它的人都能加宿主，所以只能用一次，10 分钟后过期；过期了点 **New command** 重新生成。加上 `--name "Mac mini"` 可以设定设备上显示的名字。

`pinomad leave` 把宿主从账号里移出。

## P2P 直连

设备先经服务端连上宿主。链路就绪后，Auto 会在后台尝试 WebRTC DataChannel 直连；打洞成功，对话数据就不再经过服务端；打洞失败则继续走中继。没有 TURN。

连接方式是每台宿主单独设置的，在 Settings → Hosts → Connection… 里选：Auto（默认）、Direct only（对话数据不经过 PiNomad 服务端，中继只用来建立链路）或 Relay only（只走中继，不尝试 P2P）。同一个面板显示当前路径：P2P（以及两端是局域网、tailnet 还是公网地址，完整地址点 Show addresses 展开）还是中继，以及最近一次失败的原因。

宿主从 `<数据目录>/settings.json` 的 `rtcStun` 读 STUN 服务器，并在 `hello.rtc` 里下发同一份列表：

```json
{
  "rtcStun": ["stun:stun.cloudflare.com:3478"]
}
```

默认是 Cloudflare 的公共 STUN 服务器；设为 `[]` 表示只用 host 候选（不走 STUN），也可以换成自己的 `stun:` 地址。没有 TURN，所以有些网络建不起 P2P，Auto 会继续走中继。宿主没有装上 `node-datachannel` 原生模块时（例如 npm 安装用了 `--omit=optional`），宿主照常运行，只是不再声明 `hello.rtc`。

## 密码

改密码：在 Web 或 Mac App 的账号面板里点 **Change password**，或者在 iPhone 的账号页点 **Change Password**，填当前密码和新密码（至少 12 位）。当前设备保持登录，其他设备会被退出，用新密码重新登录即可；iPhone 重新登录后推送也会恢复。

忘了密码：服务端不存邮箱，没有找回邮件。找服务端的管理员（给你邀请码的人）重置，对方会给你一个新密码；用它登录后，再改成只有你自己知道的密码。

## 账号下的设备

Web 和 Mac App 的账号面板、iPhone 的账号页都会列出登录过这个账号的每个浏览器和 App：名字、最近一次登录的时间，以及它经账号加入了哪些宿主、在每台上的状态（已登记、等宿主吊销、已吊销）。你正在用的这台标着 **This device**（iPhone 上是 **This iPhone**）。

丢了设备：点它旁边的 **Remove**，再填一次密码。服务端把它从账号里退出登录，并请它经账号加入过的每台宿主吊销它。在线的宿主立刻吊销，离线的在下次连上时吊销。最终仍由宿主决定：之后你还可以用扫码把这台设备重新配对上。

要移除正在用的这台，退出登录时勾上 **This is a shared computer**（iPhone 上是点 **Sign out** 之前打开 **Remove this iPhone from my hosts**）。服务端会像 Remove 一样，请这台设备经账号加入过的每台宿主吊销它；这台设备也会忘掉这些宿主，连同它在上面的密钥。扫码配对的宿主保留。默认不勾：宿主会一直留着吊销记录，在自己的浏览器上每次退出都勾的话，每台宿主的设备列表里会积下一堆失效的条目。

服务端只知道经过账号的那些：

- 扫码配对的设备，或者在宿主和服务端支持这个列表之前经账号配对的设备，不在列表里。到宿主的 Settings → Devices 里吊销。
- 旧版本的宿主不报告它接纳了哪些设备，服务端没法请它吊销。Remove 表单会列出这些宿主；到那里吊销，或者用 `pinomad upgrade` 升级宿主，之后的配对就能覆盖到。
- 这个列表出现之前的 App 显示为 **Unknown device**，每登录一次多一条。

## 删除账号

删除账号：点 Web 或 Mac App 账号面板最下面的 **Delete account**，或者 iPhone 账号页最下面的 **Delete Account**，再填一次密码。服务端删掉账号和它的登录会话、宿主绑定、推送登记，所有设备都会被退出。管理员账号不能删。

加入这个账号的宿主会立刻和服务端断开；要再经服务端连它，在宿主上用另一个账号重新 `pinomad join`。设备在各台宿主上的登记还在，因为这份名单由宿主自己保存：能直连宿主的设备（同一网络或 Tailscale）照常能连。要移除某台设备，到宿主的 Settings → Devices 里吊销它，或者在删除账号之前先在 **Devices** 里移除它。
