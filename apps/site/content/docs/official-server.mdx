title: Your account

Your account lives on the official server at `https://app.pinomad.si`. It vouches for your devices and forwards ciphertext when they can't reach a host directly; conversations stay end-to-end encrypted between your devices and your hosts. Setting it up is in [Getting started](/docs/).

## Sign up and sign in

Sign-up is by invite: ask for an invite code, then click **Create an account** on [app.pinomad.si](https://app.pinomad.si/) or in the Mac app's sign-in form.

- The username uses lowercase letters, digits, dots, dashes or underscores, 2–32 characters.
- The password needs at least 12 characters.
- An invite code works once and expires after 7 days. If it's used or expired, ask for a new one.

In the Mac app, the home screen shows the sign-in form until a host is connected; after that, click **Sign in** at the bottom of the sidebar. The **Server** field already says `https://app.pinomad.si`. If you run your own server, put its address there instead (see [Without an account](/docs/without-account/)).

## Hosts on your account

`pinomad up` adds a host after you confirm its code, as in [Getting started](/docs/). Running it again on a joined host needs no new code and keeps the server the host is on, and `pinomad status` shows which account that is.

For scripts and machines without anyone to confirm a code, **Add a host** has **Advanced: join with a one-time token**: a `pinomad join https://app.pinomad.si <token>` command that adds the host without a code. Anyone who has it can add a host, so it works once and expires after 10 minutes; click **New command** when it runs out. Add `--name "Mac mini"` to set the name your devices show.

`pinomad leave` takes a host off the account.

## Direct connections

Devices reach a host through the server first. Once the connection is up, Auto tries a direct WebRTC DataChannel in the background; when it succeeds, conversation data no longer passes through the server. If hole punching fails, the connection stays on the relay. There is no TURN.

The connection mode is per host, under Settings → Hosts → Connection…: Auto (the default), Direct only (never send conversation data through the PiNomad server; the relay is used only to set up the link), or Relay only (never try peer-to-peer). The same panel shows the current path: P2P (with whether each end is on a LAN, tailnet, or public address; full addresses behind Show addresses) or the relay, plus the last failure.

The host reads STUN servers from the `rtcStun` key in `<data dir>/settings.json` and advertises the same list in `hello.rtc`:

```json
{
  "rtcStun": ["stun:stun.cloudflare.com:3478"]
}
```

The default is Cloudflare's public STUN server. Set it to `[]` to use only host candidates (no STUN), or list your own `stun:` URLs. There is no TURN, so some networks cannot establish P2P; Auto keeps using the relay. If the host's `node-datachannel` native module is missing — for example after an npm install with `--omit=optional` — the host keeps running and simply does not advertise `hello.rtc`.

## Password

To change your password, click **Change password** in the account panel on the web or in the Mac app, or tap **Change Password** on the iPhone's account page. Enter your current password and a new one (at least 12 characters). This device stays signed in, and your other devices are signed out. Sign in on them again with the new password, and on the iPhone that also turns push back on.

If you forgot your password, there's no reset email, because the server doesn't store an email address. Ask the server's admin (whoever sent your invite) to reset it. They give you a new password; sign in with it, then change it to one only you know.

## Devices on your account

The account panel on the web and in the Mac app, and the iPhone's account page, list every browser and app that has signed in to your account: its name, when it last signed in, and the hosts it joined through the account, with its state on each (registered, waiting for the host to revoke it, or revoked). The one you're using is marked **This device** (**This iPhone** on the phone).

If you lose a device, click or tap **Remove** next to it and enter your password. The server signs it out of your account and asks each host it joined through the account to revoke it. A host that's online does it right away; one that's offline does it the next time it connects. The host still has the final say: you can pair the device with it again later with a QR code.

To remove the device you're using, sign out with **This is a shared computer** ticked (on the iPhone, turn on **Remove this iPhone from my hosts** before you tap **Sign out**). The server asks each host this device joined through the account to revoke it, the same way Remove does, and the device forgets those hosts along with its keys for them. Hosts you paired with a QR code stay paired. It's off by default: a host keeps every revocation, so ticking it each time you sign out of your own browser would fill each host's device list with dead entries.

The server only knows what went through the account:

- A device paired with a QR code, or paired through the account before your host and the server supported this list, isn't on it. Revoke it in the host's Settings → Devices.
- A host running an older version doesn't report the devices it admits, so the server can't ask it to revoke one. The Remove form names those hosts; revoke the device there, or update the host with `pinomad upgrade` so later pairings are covered.
- Apps from before this list show up as **Unknown device**, once per sign-in.

## Delete your account

To delete your account, click **Delete account** at the bottom of the account panel on the web or in the Mac app, or tap **Delete Account** at the bottom of the iPhone's account page, and enter your password. The server deletes the account along with its sessions, host bindings and push registrations, and every device is signed out. The admin account can't be deleted.

Hosts joined to the account lose their connection to the server right away. To reach one through a server again, run `pinomad join` on it with another account. Your devices stay registered on each host, because the host keeps that list itself: a device that reaches the host directly (same network or Tailscale) still connects. To remove a device, revoke it in the host's Settings → Devices, or remove it under **Devices** before you delete the account.
