Your account lives on the official server at `https://app.pinomad.si`. It vouches for your devices and forwards ciphertext when they can't reach a host directly; conversations stay end-to-end encrypted between your devices and your hosts. Setting it up is in [Getting started](/docs/).

## Sign up and sign in

Anyone can sign up. On [app.pinomad.si](https://app.pinomad.si/), in the Mac app's sign-in form or on the iPhone, either:

- click **Continue with Google**, **Continue with GitHub** or **Continue with Apple**, or
- click **Create an account**, enter your email address, then the 6-digit code we email you and a password of at least 12 characters.

A code works for 10 minutes and dies after five wrong tries; **Resend code** sends a new one. You're signed in as soon as the account exists.

Signing in with Google, GitHub or Apple finds your account by that sign-in, or by its email address when the provider says the address is verified and it matches your account's. When a sign-in is linked this way by its email address, the server emails you a notice. If neither matches (Apple's **Hide My Email** address, or a GitHub primary email that isn't the one you signed up with), you're asked to **Create account** or, with **I already have an account**, sign in the way you usually do and link the new one, so you don't end up with two accounts.

An account made before email sign-up still signs in with its username in the **Email** field. The first time, it asks you to add an email address and confirm it with a code; after that you sign in with the email address.

In the Mac app, the home screen shows the sign-in form until a host is connected; after that, click **Sign in** at the bottom of the sidebar. The **Server** field already says `https://app.pinomad.si`. If you run your own server, put its address there instead (see [Without an account](/docs/without-account/)).

## Sign-in methods

Settings → Account on the web and in the Mac app, and the iPhone's account page, list your **Sign-in methods**: your password and Google, GitHub and Apple. **Link** adds one (you go to the provider to pick the account and come back), and **Remove** from a method's **⋯** menu takes it away. The last way to sign in can't be removed.

The **Email** group above it changes your address: enter the new one, then the code sent to it. The old address gets a notice.

## Hosts on your account

`pinomad up` adds a host after you confirm it in the browser, as in [Getting started](/docs/). On the same computer that's a click with nothing to type; a code appears only when there's no browser there or you ask for one with `--code`. If a page asks for a code you didn't just see in your own terminal, don't enter it. Running `pinomad up` again on a joined host needs no new confirmation and keeps the server the host is on, and `pinomad status` shows which account that is.

For scripts and machines without anyone to confirm a code, **Add a host** has **Advanced: join with a one-time token**: a `pinomad join https://app.pinomad.si <token>` command that adds the host without a code. Anyone who has it can add a host, so it works once and expires after 10 minutes; click **New command** when it runs out. Add `--name "Mac mini"` to set the name your devices show.

`pinomad leave` takes a host off the account. To do it on the web or in the Mac app, for example for a machine you didn't add, go to Settings → Hosts: open a host paired here and click **Remove from account**, or pick **Remove from account** from the **⋯** menu of one that isn't, then confirm (see [Confirming changes](#confirming-changes)): the host stops connecting through the server until you run `pinomad up` on it again.

## Direct connections

Devices reach a host through the server first. Once the connection is up, Auto tries a direct WebRTC DataChannel in the background; when it succeeds, conversation data no longer passes through the server. If hole punching fails, the connection stays on the relay. There is no TURN.

The connection mode is per host: in Settings → Hosts, open the host with the arrow on its row, then pick under Connection: Auto (the default), Direct only (never send conversation data through the PiNomad server; the relay is used only to set up the link), or Relay only (never try peer-to-peer). The same page shows the current path: P2P (with whether each end is on a LAN, tailnet, or public address; full addresses behind Show addresses) or the relay, plus the last failure.

A host's page also lists the routes that reach it: the account relay, a tailnet or LAN address, or this computer. Routes the connection mode leaves out read Off.

The host reads STUN servers from the `rtcStun` key in `<data dir>/settings.json` and advertises the same list in `hello.rtc`:

```json
{
  "rtcStun": ["stun:stun.cloudflare.com:3478"]
}
```

The default is Cloudflare's public STUN server. Set it to `[]` to use only host candidates (no STUN), or list your own `stun:` URLs. There is no TURN, so some networks cannot establish P2P; Auto keeps using the relay. If the host's `node-datachannel` native module is missing — for example after an npm install with `--omit=optional` — the host keeps running and simply does not advertise `hello.rtc`.

## Password

To change your password, click **Change password** under Sign-in methods in Settings → Account on the web or in the Mac app, or, on the iPhone, tap the account button at the top left of the home screen and tap **Change** next to Password. Enter your current password and a new one (at least 12 characters). This device stays signed in, and your other devices are signed out. Sign in on them again with the new password, and on the iPhone that also turns push back on.

An account that signs in only with Google, GitHub or Apple has no password; **Set password** adds one, confirmed with a code sent to your email address.

If you forgot your password, click **Forgot password?** on the sign-in form, enter your email address, then the code we send and a new password. Your sessions everywhere end.

## Confirming changes

Removing a device or a host, changing your email address or sign-in methods, setting a password and deleting the account act on more than this device, so they ask you to confirm first: with your password, or, if the account has none, with a code emailed to you (**Send code**). On the web and in the Mac app, confirming once covers the next five minutes.

## Devices on your account

The Signed-in devices section of Settings → Account on the web and in the Mac app, and of the iPhone's account page, lists every browser and app that has signed in to your account: its name, when it last signed in, and the hosts it joined through the account, with its state on each (registered, waiting for the host to revoke it, or revoked). The one you're using is marked **This device** (**This iPhone** on the phone).

If you lose a device, pick **Remove** from its **⋯** menu (on the iPhone, the same menu, or swipe left on it) and confirm. The server signs it out of your account and asks each host it joined through the account to revoke it. A host that's online does it right away; one that's offline does it the next time it connects. The host still has the final say: you can pair the device with it again later with a QR code. On the web and in the Mac app the device then leaves the list.

To remove the device you're using, sign out with **This is a shared computer** ticked (on the iPhone, tap **Sign Out** and turn on **Remove this iPhone from my hosts** before you confirm). The server asks each host this device joined through the account to revoke it, the same way Remove does, and the device forgets those hosts along with its keys for them. Hosts you paired with a QR code stay paired. It's off by default: a host keeps every revocation, so ticking it each time you sign out of your own browser would fill each host's device list with dead entries.

The server only knows what went through the account:

- A device paired with a QR code, or paired through the account before your host and the server supported this list, isn't on it. Unpair it in the host's Settings → Devices.
- A host running an older version doesn't report the devices it admits, so the server can't ask it to revoke one. The Remove form names those hosts; unpair the device there, or update the host with `pinomad upgrade` so later pairings are covered.
- Apps from before this list show up as **Unknown device**, once per sign-in.

## Delete your account

To delete your account, click **Delete account** under Danger zone in Settings → Account on the web or in the Mac app, or tap **Delete Account** under Danger Zone on the iPhone's account page (the button at the top left of the home screen), and confirm. The server deletes the account along with its email address, sign-in methods, sessions, host bindings and push registrations, and every device is signed out. If you linked Apple, the server also revokes PiNomad's access to your Apple ID.

Hosts joined to the account lose their connection to the server right away. To reach one through a server again, run `pinomad join` on it with another account. Your devices stay registered on each host, because the host keeps that list itself: a device that reaches the host directly (same network or Tailscale) still connects. To remove a device, unpair it in the host's Settings → Devices, or remove it under **Devices** before you delete the account.
