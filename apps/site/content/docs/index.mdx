title: Getting started
description: Create an account, add your host with one command, sign in on your other devices, and turn on push.
---

PiNomad comes down to two things: your **host** (the machine that runs the agent) joins your account, and your **devices** sign in to it. The official server at `https://app.pinomad.si` does the rest. Your devices find and reach the host from anywhere, and conversations stay end-to-end encrypted between them; the server only forwards ciphertext when a device can't reach the host directly.

To use PiNomad without an account (one machine, your local network or tailnet, or a server you run), see [Without an account](/docs/without-account/).

## 1. Create an account

Sign-up is by invite. Open [app.pinomad.si](https://app.pinomad.si/) (or the sign-in form in the Mac app), click **Create an account**, and enter the invite code, a username and a password. You're signed in as soon as the account exists. Username rules and the rest are in [Your account](/docs/official-server/).

## 2. Add your host

On the machine that should run the agent (macOS or Linux), run:

```sh
curl -fsSL https://pinomad.si/install.sh | sh
pinomad up
```

The first line installs pinomad with its own Node. If the script says so (it does on a new Mac), run `pinomad up` in a new terminal window: it put pinomad on your PATH, and only new windows read that. `pinomad up` then asks how your other devices should reach this host; press Enter to go through the official server. It prints a page to open and a code like `WDJB-MJHT`, and opens the page in your browser when it can:

1. On the page, signed in to your account, enter the code. **Add a host** in the web or Mac app has the same field.
2. Check the name and system it shows, and confirm only if you started this on that machine.
3. Back in the terminal, `pinomad up` adds the host to your account and installs it as a service that starts at boot.

To add another host later, run the same two lines on that machine.

The script puts Node and pinomad in `~/.pinomad/runtime` and the `pinomad` command in `~/.local/bin`, and adds that directory to your shell profile (`~/.zshrc`, `~/.bashrc` and so on) when it isn't on your PATH yet. It covers Apple silicon Macs and Linux on x64 or arm64 (glibc). Anywhere else, or to use a Node 25+ you already have, run `npm i -g pinomad` and then `pinomad up`. If pinomad is already installed with npm, the script leaves it alone; run `pinomad upgrade`, then `pinomad up`.

## 3. Sign in on your other devices

Sign in with the same username and password, and the device pairs with every host on your account that's online, with no QR code.

- **Web:** [app.pinomad.si](https://app.pinomad.si/) in any modern browser.
- **Mac app** (Apple silicon): the signed DMG from [GitHub Releases](https://github.com/bubbleptr/pinomad/releases); it updates itself.
- **iPhone:** tap **Sign in** in Settings. The app can't create accounts, so sign up on the web or in the Mac app first. The iPhone app is in internal TestFlight for now.

Paired hosts show **Connect**. A host that wasn't paired on its own, for example one you removed from this device before, shows **Pair**; click it to pair.

Then sign in to a model provider under Settings → Providers: a subscription you already pay for (Claude, ChatGPT, Copilot, …), an API key, or your own OpenAI- or Anthropic-compatible endpoint.

## 4. Push notifications

The iPhone app can notify you when a conversation is waiting for your answer, finishes, or fails. Turn it on under Settings → Notifications in the app; it's off by default and covers every host. The iPhone has to be signed in to the same account the host joined. A notification carries only the conversation title and the event, never the question or the reply. The title passes through the server and Apple. More details: [Usage](/zh/docs/usage/) (Chinese).

## Look after the host

```sh
pinomad status      # the account, LAN port, service, and whether the host answers
pinomad upgrade     # install pinomad@latest, wait for running tasks, restart
```

`pinomad upgrade` updates pinomad only; running the install script again updates its Node too. Service flags, logs and platform caveats: [Running as a service](/zh/docs/service/) (Chinese).

To uninstall, run `pinomad service uninstall`, then delete `~/.pinomad/runtime`, `~/.local/bin/pinomad`, and the line in your shell profile that ends in `# added by https://pinomad.si/install.sh`. Your data in the rest of `~/.pinomad` stays until you delete it.

| Client | How to get it |
|---|---|
| Web | [app.pinomad.si](https://app.pinomad.si/); the host also serves it (`pinomad link`) |
| macOS (Apple silicon) | Signed DMG from [GitHub Releases](https://github.com/bubbleptr/pinomad/releases); updates itself |
| iOS | Internal TestFlight only for now |
