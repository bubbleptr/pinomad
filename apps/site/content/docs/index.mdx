## Quick start

The host runs on macOS or Linux. The install script brings its own Node:

```sh
curl -fsSL https://pinomad.si/install.sh | sh
pinomad host        # data and credentials live in ~/.pinomad
pinomad link        # in another terminal: prints a browser link to the web client
```

The script puts Node and pinomad in `~/.pinomad/runtime` and the `pinomad` command in `~/.local/bin`, and prints the line to add to your shell profile if that directory isn't on your PATH. It covers Apple silicon Macs and Linux on x64 or arm64 (glibc). Anywhere else, or to use a Node 25+ you already have, install with `npm i -g pinomad` instead.

Sign in to a model provider under Settings → Providers: a subscription you already pay for (Claude, ChatGPT, Copilot, …), an API key, or your own OpenAI- or Anthropic-compatible endpoint. To click around without one, `pinomad host --faux "hi"` runs a scripted fake model.

## Connect your other devices

Open a port for paired devices, then pair each device with its own QR code:

```sh
pinomad host --remote-port 7422
pinomad pair        # one-time QR code and link, expires after 5 minutes
```

Scan the code with the iPhone app, or paste the link into the Mac app. The remote port accepts paired devices only; revoke them under Settings → Devices.

The pairing link always keeps a legacy socket URL and can carry the reachable relay and direct candidates. Without `--public-url` the direct address is the LAN address the host detects; on a tailnet or behind a tunnel, add `--public-url http://<tailnet-ip>:7422` so it points there. When the host is joined to a relay, older clients keep using the relay URL. To reach a host at home from anywhere, [use the official server](/docs/official-server/) or run your own relay on a VPS: see [Remote access](/zh/docs/remote-access/) (Chinese).

## WebRTC direct connections

When a relay is available, clients connect through it first. Once the connection is up, Auto tries a direct WebRTC DataChannel in the background; when it succeeds, conversation data no longer passes through the server. If hole punching fails, the connection stays on the relay. There is no TURN.

The connection mode is per host, under Settings → Hosts → Connection…: Auto (the default), Direct only (never send conversation data through the PiNomad server; the relay is used only to set up the link), or Relay only (never try peer-to-peer). The same panel shows the current path: P2P (with whether each end is on a LAN, tailnet, or public address; full addresses behind Show addresses) or the relay, plus the last failure.

The host reads STUN servers from the `rtcStun` key in `<data dir>/settings.json` and advertises the same list in `hello.rtc`:

```json
{
  "rtcStun": ["stun:stun.cloudflare.com:3478"]
}
```

The default is Cloudflare's public STUN server. Set it to `[]` to use only host candidates (no STUN), or list your own `stun:` URLs. There is no TURN, so some networks cannot establish P2P; Auto keeps using the relay. If the host's `node-datachannel` native module is missing — for example after an npm install with `--omit=optional` — the host keeps running and simply does not advertise `hello.rtc`.

## Keep it running

Install the host as a user service (LaunchAgent on macOS, systemd user unit on Linux) so it starts at boot and restarts on crash:

```sh
pinomad service install --remote-port 7422
pinomad service status
pinomad upgrade     # install pinomad@latest, wait for running tasks, restart
```

Service flags, logs, and platform caveats: [Running as a service](/zh/docs/service/) (Chinese). `pinomad upgrade` updates pinomad only; running the install script again updates its Node too.

To uninstall a script install, run `pinomad service uninstall`, then delete `~/.pinomad/runtime` and `~/.local/bin/pinomad`. Your data in the rest of `~/.pinomad` stays until you delete it.

## Clients

| Client | How to get it |
|---|---|
| Web | Served by the host itself (`pinomad link`) and by the relay; any modern browser |
| macOS (Apple silicon) | Signed DMG from [GitHub Releases](https://github.com/bubbleptr/pinomad/releases); updates itself |
| iOS | Internal TestFlight only for now |
| Linux, Windows | Use the web client |
