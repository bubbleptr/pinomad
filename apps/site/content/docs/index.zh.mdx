## 快速上手

宿主需要 Node 25+，支持 macOS 和 Linux。

```sh
npm i -g pinomad
pinomad host        # 数据和凭据都在 ~/.pinomad
pinomad link        # 另开一个终端：打印 Web 客户端的浏览器链接
```

模型在 Settings → Providers 里接入：用已经在付费的订阅登录（Claude、ChatGPT、Copilot 等）、填 API key，或者填你自己的 OpenAI / Anthropic 兼容 endpoint。还没有的话，`pinomad host --faux "hi"` 会用一个脚本化的假模型跑起来，可以先点点看。

## 连上其他设备

给配对设备开一个端口，然后每台设备各扫一个二维码：

```sh
pinomad host --remote-port 7422
pinomad pair        # 一次性的二维码和链接，5 分钟后过期
```

iPhone App 扫码，Mac App 粘贴链接。远程端口只接受配对过的设备，不需要的设备可以在 Settings → Devices 里吊销。

配对链接始终保留 legacy socket 地址，也可以带上可远程访问的中继和直连候选。没有 `--public-url` 时，直连地址用宿主探测到的局域网地址；在 tailnet 里或走隧道时，加上 `--public-url http://<tailnet-ip>:7422`，让它指向那个地址。宿主加入了中继时，旧客户端继续使用链接里的中继地址。宿主在家、人在外面也想连，就在 VPS 上跑中继，见[远程访问](/zh/docs/remote-access/)。

## WebRTC 直连

宿主可以应答 WebRTC offer，把安全通道放在可靠、有序的 DataChannel 上，而不是 WebSocket。客户端真正使用 P2P 的能力（以及"连接方式"设置）会在后续版本推出；这个版本只有宿主侧和协议。

宿主从 `<数据目录>/settings.json` 的 `rtcStun` 读 STUN 服务器，并在 `hello.rtc` 里下发同一份列表：

```json
{
  "rtcStun": ["stun:stun.cloudflare.com:3478"]
}
```

默认是 Cloudflare 的公共 STUN 服务器；设为 `[]` 表示只用 host 候选（不走 STUN），也可以换成自己的 `stun:` 地址。没有 TURN：P2P 连不上时，仍然回落到现有的中继 / 直连 WebSocket。宿主没有装上 `node-datachannel` 原生模块时（例如 npm 安装用了 `--omit=optional`），宿主照常运行，只是不再声明 `hello.rtc`。

## 常驻运行

把宿主装成当前用户的服务（macOS 是 LaunchAgent，Linux 是 systemd 用户单元），开机自启、崩溃自动拉起：

```sh
pinomad service install --remote-port 7422
pinomad service status
pinomad upgrade     # 装上 pinomad@latest，等正在跑的任务结束后重启
```

服务参数、日志和各平台的注意事项见[常驻运行](/zh/docs/service/)。

## 客户端

| 客户端 | 获取方式 |
|---|---|
| Web | 宿主自己提供（`pinomad link`），中继也提供；现代浏览器都能用 |
| macOS（Apple 芯片） | [GitHub Releases](https://github.com/bubbleptr/pinomad/releases) 上签名过的 DMG，会自动更新 |
| iOS | 目前只在 TestFlight 内部测试 |
| Linux、Windows | 用 Web 客户端 |
