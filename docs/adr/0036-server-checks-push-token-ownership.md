# ADR-0036：服务端核对推送 token 属于发起宿主的账号

- 状态：Accepted
- 日期：2026-10-31
- 修订 ADR-0025 §5（服务端开始保存 token 和它属于哪个账号）和"后果"里开放注册门槛的做法；补充 §4（每次发送多核对一项 token 归属）

## 背景

ADR-0025 让宿主持有设备的 APNs token，经控制连接发 `push` 帧请服务端转发。服务端每次发送只核对这台宿主绑定在某个账号上，不核对 token 属于谁。只有作者一个账号时没问题；开放注册（#449）之后，任何绑定了账号的宿主都能请服务端给它知道的任意 token 发通知，例如一台已经被吊销的设备的 token，或者泄露出去的 token。ADR-0025 把"服务端核对 token 属于这个账号"定为开放注册的门槛，并举了"设备向服务端登记、宿主只拿到一个不透明的句柄"的例子。

ADR-0025 当时拒绝"设备直接向服务端登记"，理由是扫码配对的设备不一定登录过账号。2026-10-30 的产品决定去掉了这个前提：推送本来就只能经官方服务端（只有它有 APNs 密钥），所以要求设备登录宿主所在的同一个账号才有推送。

## 决策

1. **设备登录后向服务端登记 token，服务端记下它属于哪个账号。** 新增 `POST /api/push-tokens`（`{ apns, environment }`，登记或刷新）和 `POST /api/push-tokens/remove`（同样的参数，删除），要求已登录，鉴权和 Origin 规则与其余 `/api/*` 相同。token 的格式检查和宿主一致：十六进制，不超过 256 个字符，统一转小写。不用 `DELETE` 带请求体，也不把 token 放进 URL：反向代理的访问日志会记下 URL。

2. **`(token, environment)` 同一时间只属于一个账号。** 同一台设备在另一个账号登录后再登记，记录移到新账号下，以最后一次登记为准。这样设备退出 A、登录 B 时，即使退出时的删除请求没发出去，A 的宿主也推不到它。每个账号最多保留 32 条，超出时删掉最久没刷新的。

3. **推送时核对归属。** 服务端收到 `push` 帧时，查出发起宿主绑定的账号，再查 `(token, environment)` 是否登记在这个账号下；不是就回 `rejected`，原因 `token_not_registered`，不发给 Apple。宿主遇到 `rejected` 照旧只记日志、不删本地登记（ADR-0025 §5），所以设备之后登录账号并登记，推送会自己恢复，不用重新调 `setPushToken`。

4. **不引入句柄，协议不变。** 宿主照旧持有 token，`setPushToken`、`push` 帧、`pinomad.push` 文档和 Rust 核心都不改。宿主是设备完全信任的一方（能进宿主就等于拿到 shell，ADR-0008 §8），它知道 token 不增加风险；token 一旦泄露，服务端的归属核对也让它在别的账号下没用。句柄只会多一层映射和一次协议升级，换不来更多保护。

5. **记录什么时候删除。**
   - 设备关掉推送或退出登录时，先调 `remove`；
   - "退出所有会话"（`POST /api/sessions/revoke-all`）和服务端改密码（`pinomad server passwd`）删掉这个账号的全部记录，删除账号时级联删除。这两个操作都是在怀疑账号被盗时用的，盗用者登记的 token 不能留下；
   - APNs 回 410 时，服务端照 ADR-0025 §5 的规则删除自己的记录：只在登记时间早于 APNs 给的失效时间时才删，迟到的 410 不会删掉刚刷新过的登记。结果照旧转给宿主；
   - 90 天没刷新的记录视为不存在，并在登记时顺手清掉。App 每次连上、回到前台都会刷新（ADR-0025 §9 的时机）。

   记录不跟登录会话绑定：会话 30 天到期、不续期，绑在会话上会让推送在一个月后悄悄失效。

6. **上线当天就核对，不加开关。** 不登记的客户端只有作者手机上的 0.8.0 TestFlight 版；iOS 的登记紧跟服务端发布。

## 考虑过的方案

- **句柄**（ADR-0025"后果"里举的例子）：设备登记后服务端发一个不透明句柄，宿主只存句柄。宿主拿不到 token，但见第 4 条，这不增加保护；代价是改 `setPushToken` 和 `push` 帧、升协议次版本号、同步 Rust 核心和对照向量，还要处理老宿主和老客户端。
- **宿主替设备登记**：扫码配对的设备不用登录。但服务端只能相信宿主说的"这个 token 属于我的账号"，和现在没有区别。
- **记录绑在登录会话上**：退出登录或会话到期自动失效，最干净；但会话 30 天到期不续期，推送会在一个月后无声地停掉。
- **`(user, token, environment)` 唯一**：同一个 token 可以同时登记在多个账号下。设备换账号后，如果旧账号的删除请求没到，旧账号的宿主还能推给它。
- **加开关，等 iOS 发布后再打开**：没有别的用户，过渡期只影响作者自己，不值得多一个配置项。

## 后果

- 服务端开始保存 APNs token、环境、所属账号和登记时间，这要写进隐私政策（#455）。通知内容照旧只转发、不保存。
- 推送需要设备登录宿主所在的账号；只扫码配对、没登录的设备收不到推送。iOS 在推送开关旁边说明这一点。
- 老宿主不受影响：帧没变，核对在服务端。
- 自部署的服务端也会核对。它们没有官方 App 的 APNs 密钥，实际影响只在自己打包 App 的部署者身上。
- 拆两个 PR：服务端（本 ADR、表、接口、核对，见 #448），iOS（登录后登记、退出时删除、开关旁的说明）。
