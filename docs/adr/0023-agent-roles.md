# ADR-0023：具名 Agent——放在数据目录的 Markdown 文件，用时抄一份，子代理上锁定模型

- 状态：Accepted
- 日期：2026-10-13

## 背景

PiNomad 的优势之一是多 provider 和可定制。最直接的需求是"某类活固定交给某个模型"，比如改完代码换个模型做 review。现在的 `subagent` 只有 `task`、`description`、`model`、`thinkingLevel` 四个参数，每次都由模型临时决定用什么模型，没有可复用、有名字的配置。

几个现状：

- 上游 1.0.4 / 1.1.0 都没有具名代理或 workflow 的概念（调研见 [#65](https://github.com/bubbleptr/pinomad/issues/65)）。Durable 每条对话的 `AgentState` 能装下模型、思考等级、提示词、工具，但名字、文件格式、发现和按名字调用都要自己做。
- 同类产品都用"文件里写一份配置"：Claude Code 是 `.claude/agents/*.md`（frontmatter 加提示词正文，调用参数优先于文件里的 `model`），opencode 是 Markdown 且文件名即名字，Codex 是 TOML；三家都是项目级优先于用户级。Pi CLI 只有示例扩展（`~/.pi/agent/agents/*.md`、`presets.json`）。
- 跨工具的上下文从 `~/.agents/` 读（ADR-0006 的 Skills、ADR-0012 的 `mcp.json`）；PiNomad 自己的配置在数据目录（ADR-0021 的 `settings.json`）。
- `subagent` 只给模型调用，codemode 脚本里调不了（ADR-0013）；子代理里不能再派子代理。

## 决策

1. **具名 Agent 是宿主级配置，放在数据目录的 `agents/<name>.md`**（默认 `~/.pinomad/agents/`，跟着 `--data-dir` / `PINOMAD_DATA_DIR` 走）。不读 `~/.agents/`，不做项目级；每台宿主各有一套，宿主之间不同步。它是 PiNomad 自己的配置，不是跨工具共享的上下文。

2. **格式：Markdown 加 YAML frontmatter，文件名就是名字。**
   - 名字只能是小写字母、数字、连字符，最长 32 个字符。
   - `description` 必填，模型靠它判断什么时候用；`model`（`provider/modelId`）和 `thinkingLevel` 选填；正文是提示词。
   - 不做工具白名单：子代理有 `bash`，白名单保证不了"只读"，具名 Agent 也不应约束太紧。不带 `skills` 字段：宿主上安装的 Skills 所有对话都能用。
   - 不兼容 Claude Code 等别家的格式（ADR-0001）：它们的模型别名、工具名在 PiNomad 里都对不上。

3. **客户端能看能改，宿主监视目录。** 设置里列出所有具名 Agent，可以新建、编辑、删除，由宿主写文件，经一条宿主流把完整快照推给所有在线设备。宿主监视 `agents/` 目录，手改文件马上生效。这和 ADR-0021 §4 的 `settings.json` 不同：设置文件只由宿主写，具名 Agent 却是用户常会手写的 Markdown。

4. **三种用法，每个具名 Agent 都能用于任何一种。**
   - 子代理：`subagent` 新增 `role` 参数，工具描述列出所有可用的名字和 `description`。
   - `@` 提及：消息里带 `@reviewer` 时，宿主在这一轮附上一句明确指令，要求主模型把相关工作交给这个具名 Agent，由主模型调 `subagent` 并写好任务描述。不跳过主模型：子代理拿不到对话上下文，用户的原话通常离开上下文就看不懂。
   - 顶层对话：新建对话时可以选一个，默认不选；只能在开始时选，中途不能换。
   - 不加"只能当子代理"或"只能开对话"的标记。

5. **模型和思考等级：子代理上锁定，顶层对话只定初始值。**
   - 子代理用具名 Agent 时，定义里写了的 `model` / `thinkingLevel` 就以定义为准，调用时再传这两个参数直接报错；定义里没写的照旧可以传，不传就沿用父对话。
   - 顶层对话里，具名 Agent 的模型和思考等级只是初始值，之后用户仍可以在输入框里换。子代理是模型在发起，要防它顺手改掉；顶层对话是用户自己在用，不必锁。

6. **提示词接在原有说明后面，不替换。** 子代理：接在固定的子代理说明（不能提问、最后一条消息就是结果）后面。顶层对话：接在系统提示词后面。项目上下文、Skills、MCP 照常加载。

7. **用的时候抄一份。** 顶层对话创建或子代理派出时，具名 Agent 的提示词、模型、思考等级写进这条对话自己的 `AgentState`，对话只记下名字用于显示。之后改或删这个具名 Agent，已有的对话和子代理都不受影响，重启恢复的也还是当时那份。

8. **出错直接报错，不回落。**
   - 文件写错（frontmatter 解析不了、缺 `description`、名字不合规）：设置页列出来并标上原因，`@` 菜单和工具描述里都不出现。
   - 模型用不了（没登录、不存在）：新建对话时直接报错；子代理调用时工具返回错误，说明哪个模型用不了，由主模型决定怎么办。
   - 悄悄回落到父对话的模型，正好违背"固定交给某个模型"。

9. **边界。**
   - `subagent` 仍然只给模型调用（ADR-0013），codemode 脚本里用不了具名 Agent；子代理里仍然不能再派子代理，用具名 Agent 开的顶层对话可以照常派。
   - "按固定顺序让几个具名 Agent 接力"属于 workflow，另行设计，可以直接引用具名 Agent。
   - 具名 Agent 是数据文件，不是代码，不涉及 ADR-0004 的插件协议。

## 考虑过的方案

- **放在 `~/.agents/agents/`，加项目级 `.agents/agents/`**：和 Skills、`mcp.json` 放在一起，项目里还能提交专用的具名 Agent。但具名 Agent 是 PiNomad 自己的配置（模型名、思考等级只对 PiNomad 有意义），客户端也要能编辑；项目级等真有需要再加。
- **存进 `settings.json`**：和其他宿主设置在一起。但多行提示词写进 JSON 不好手改，也没法一个具名 Agent 一个文件地复制、分享。
- **调用参数优先于定义（Claude Code 的做法）**：模型能临时换掉，更灵活。但目的就是"固定交给某个模型"，允许覆盖等于模型可以顺手改掉。
- **每轮重新读具名 Agent 文件**：改了马上影响所有对话。但正在跑的对话会中途换提示词，恢复时的配置也和当时不一样。
- **工具白名单**：能表达"只读审阅者"。但有 `bash` 就保证不了只读；真要只读，得先补上不依赖 `bash` 的 grep / find / ls（路线图 M2）。
- **`@` 直接把消息交给子代理**：少一次主模型调用。但子代理没有对话上下文。
- **按用法加 `mode` 标记（opencode 的 `primary` / `subagent`）**：多一个字段要维护，现在看不出需要。

## 后果

- ADR-0006 "上下文只从项目和 `~/.agents` 读取"不受影响：具名 Agent 是宿主配置，不是上下文来源。
- 协议新增：具名 Agent 的宿主流和新建、修改、删除调用，新建对话带可选的具名 Agent，`subagent` 新增 `role` 参数。都是新增，按 ADR-0018 涨次版本号。
- 备份数据目录时多一个 `agents/` 目录。
- 移动端第一版只显示列表、能选，编辑以后单独做；`@` 菜单以后和 @ 文件补全共用。
- 以后可能的后续：项目级具名 Agent、工具白名单（等不带 `bash` 的只读工具集）、`skills` 字段、对话中途换具名 Agent、workflow。都记在路线图。
