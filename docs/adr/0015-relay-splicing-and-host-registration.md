# ADR-0015：自部署中继——按连接拼接、宿主用独立签名密钥登记

- 状态：Accepted
- 日期：2026-10-09

## 背景

ADR-0008 第二期定了方向：宿主和客户端都主动连中继，中继按宿主身份把两端接起来，只转发密文。落地时还有几件事要定：一台宿主同时连多台设备时中继怎么转发，宿主怎么证明自己就是某个身份，Web 客户端从哪里加载。

直接的场景是一台 7x24 常驻在家里局域网的 Linux 宿主，手机在外面连它；中继跑在用户自己的 VPS 上，前面由 Caddy 终止 TLS。

## 决策

1. **中继按连接拼接，不做多路复用。** 宿主保持一条控制连接（`/host`）。设备连 `/c/<hostId>` 时，中继生成一个随机 `connId`，经控制连接通知宿主；宿主为这台设备单独开一条数据连接 `/accept/<connId>`，中继把两条 WebSocket 逐帧接起来。宿主把数据连接交给和局域网监听器相同的 IK 握手，配对、设备登记、吊销都不变，设备端代码也不用改。设备在接通前发出的消息（握手第一条）由中继缓存，接通后按顺序转给宿主。

2. **宿主用一对单独的 Ed25519 密钥登记，不复用 Noise 的 X25519 宿主密钥。** `hostId` 就是这把 Ed25519 公钥的 base64url。中继发一个随机 nonce，宿主对 `pinomad-relay/1`、中继的公开 origin、`hostId`、nonce 签名。把 origin 签进去，是为了让恶意中继拿到的签名不能转到别的中继上冒名登记。
   - 用 X25519 做 DH 挑战也能证明持有私钥，但那等于把 Noise 的静态私钥用在第二个协议里、把 DH 结果交给中继，跨协议复用很难论证安全。单独一把签名密钥只用来证明对 `hostId` 的使用权；端到端安全仍然只依赖设备固定认的 X25519 宿主公钥，登记密钥泄露最多让别人抢占 `hostId`，读不到流量。

3. **中继只接受白名单里的宿主。** 中继启动时用 `--allow-host` 列出允许登记的 `hostId`，防止自己的 VPS 变成公共中继。同一 `hostId` 的新登记替换旧的控制连接（宿主重连时旧连接可能半开）。中继不持久化任何东西。

4. **中继用 HTTPS 提供它自己检出的 Web 客户端。** 配对链接是 `<中继 origin>/#pair=…&url=wss://<中继>/c/<hostId>`，开了中继时优先于局域网地址。
   - 页面代码的可信来源就是用户自己的中继：中继由用户部署，信任上和宿主一致，又比局域网 HTTP 多了 TLS（ADR-0008 后果里的主动篡改问题在公网上得到缓解）。
   - 代价是中继和宿主的版本可能不一致。客户端发现宿主的协议更新时会进入 `outdated` 状态并重新加载一次；仍不一致就要两边一起升级。把页面经隧道从宿主取来能保证版本一致，但要在中继上做 HTTP-over-tunnel；和宿主版本严格同步的问题留给移动端（原生 App 随宿主走）去解决。

5. **中继的关闭码用 46xx**（`RELAY_CLOSE`，`packages/protocol/src/relay.ts`），和宿主自己的关闭码（如 4401）分开，客户端以后可以据此区分"宿主不在线"和"宿主拒绝了这台设备"。

## 考虑过的方案

- **一条宿主连接上多路复用所有设备**：中继要理解帧里的流 ID，宿主要自己做背压和流的生命周期；按连接拼接时这些都由 WebSocket 本身负责，中继几乎没有协议逻辑。代价是每台设备多一次宿主到中继的握手，设备数量很少，可以接受。
- **X25519 DH 挑战**：不用多一把密钥，但有上面说的跨协议复用问题。
- **共享口令代替签名**：口令要在宿主和中继两边保管，泄露后能冒名登记；签名方案里中继只存公钥。
- **静态托管（Pages 等）提供 Web 客户端**：多一个部署和信任对象，和中继分开升级同样有版本问题。

## 后果

- 宿主数据目录里多一个 `relay-key`（0600）；`bun run relay-id` 打印 `hostId`，运维时要把它加进中继的 `--allow-host`。
- `apps/relay` 依赖 `apps/host` 的 `web-client.ts` 来提供页面；宿主测试反过来依赖中继。两者都在同一个源码检出里，VPS 上也是检出整个仓库。
- 中继能看到的元数据和 ADR-0008 说的一样：哪个宿主、哪台设备连接、何时、流量多大；另外它知道每台宿主的 Ed25519 公钥。
- 任何人都能连 `/c/<hostId>` 让宿主开数据连接；宿主同时只处理有限个未完成的接入（默认 16），多余的由中继超时关闭。中继本身还没有限流。
- 二维码里只有一个连接地址；局域网和中继两个候选地址自动选择留到以后（设备现在只存一个 `url`）。
