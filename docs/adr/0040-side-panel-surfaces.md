# ADR-0040：侧面板是固定三个 Surface 的容器，页切换放在聊天区头部

- 状态：Accepted
- 日期：2026-11-03
- 修订：ADR-0039 §4（"右侧只保留 Tasks"）

## 背景

ADR-0039 拆掉 Threads 之后，Web/桌面端的右侧面板只剩 Tasks：当前家族的 Foreground 子代理，点开是只读详情。改动放在一个 720px 宽的 Changes 对话框里，挡住对话；终端还没有，要在对话的检出里跑命令只能切到别的终端窗口，还得自己找到 worktree 在哪。

Overview 浮层（#215）已经汇总了工作区、改动、用量、子代理和工具来源。用户希望它保持轻量：有时只想扫一眼，不想看细节。浮层放不下的详情——完整的 diff、子代理的对话、需要大块空间的终端——应该在右侧面板里，和对话并排看。

M11 把右侧面板改成能放多个页的容器。要定的是：有哪些页、页跟着什么变、在哪切换、多个终端怎么切换。

## 决策

1. **侧面板是固定三个 Surface 的容器：Tasks、Changes、Terminal。** 不做注册表，加 Surface 时改代码。Tasks 的内容和行为照 ADR-0038、0039 不变；Changes 取代 Changes 对话框；Terminal 是新的。Overview 浮层保留，只放摘要，点摘要打开对应的 Surface。

2. **所有 Surface 跟着主区对话的 root 家族走。** 一个家族只在一个执行检出上（Fork 和子代理都用父对话的检出），反过来一个项目目录可以被多个家族共用，所以家族是更细、也更简单的键。在同一家族的根对话、Fork 和子代理之间切换时，三个 Surface 都不重置；切到另一个家族时，Tasks 关掉详情（现有行为），Changes 重新取，Terminal 换成那个家族的终端。项目目录被多个家族共用时，Changes 保留"这是项目目录里未提交的改动，和其他对话共用"的说明。

3. **页切换是聊天区头部右端的三个图标，取代原来的 Side panel 按钮。** 面板关着时点图标，打开到那一页；面板开着、停在别的页时点图标，切过去；点当前页的图标，关掉面板。当前页的图标是按下状态。面板记住上次打开的页（存在本地，全局一个值），默认关着，打开对话不会自动弹出。其他入口直接落到对应的页：Overview 的改动 → Changes，Overview 的子代理和对话里的子代理卡片 → Tasks。

4. **头部只盖聊天区，侧面板通高。** 面板最上面一行和聊天区头部同高（40px）、齐平，放当前 Surface 的状态和操作，不写页名（页名由图标给出）：
   - Tasks：列表时是运行中和已完成的数量；详情时是返回、状态点和子代理的名字。
   - Changes：分支、文件数和增删行数、刷新。
   - Terminal：终端的标签栏（见第 5 条）。

   桌面端这一行除按钮外的空白处可以拖动窗口，和头部一样。

5. **终端归 root 家族所有，一个家族可以开多个。** 终端由宿主运行，工作目录是这个家族的执行检出；每个家族最多 8 个，超出由宿主拒绝；根对话归档时宿主关掉这个家族的全部终端。Terminal 的首行就是标签栏：每个终端一个标签，按创建顺序排列，新开的排在最后并选中；放不下的收进末尾的下拉菜单，当前选中的始终在外面；右侧是新建（`+`）和当前终端的菜单（重命名、重启、关闭）。关闭不放在每个标签上：标签本身是按钮，里面再嵌按钮对键盘和读屏都不友好。
   - 标签名默认取 shell 设置的窗口标题，没有时是 `Terminal N`；重命名后固定用这个名字。
   - 进程退出后标签保留，变灰并显示退出码，可以重启，不会自动消失。
   - 没有终端时显示 "New terminal" 按钮，不自动新建：新建会在宿主上起进程。
   - 客户端在内存里记住每个家族上次选中的终端，切回来时选回它。

6. **活动指示挂在 Tasks 图标上。** Tasks 不可见时（面板关着，或停在别的页）显示，仍然只反映 Tasks 里的 Foreground 活动，承接 ADR-0039 §4 的最后一句。

7. **Changes 只在可见时拉取**，一次运行结束时自动刷新一次（Changes 对话框现在就是这样）。

8. **窄屏仍是全屏对话框。** 窄屏头部放不下三个图标，所以只留一个按钮，打开对话框并停在上次的页；对话框顶部是三个图标和关闭按钮。Terminal 页的标签栏在它下面一行，这是唯一出现两行的情况。

## 考虑过的方案

- **面板里两排标签（上排是页，下排是终端）**：页切换和终端切换都在面板里，但多占一行竖向空间，面板顶部和聊天区头部也对不齐。
- **终端直接排进页签那一排**（`Tasks | Changes | zsh | dev | +`）：只有一排，但固定的页和可关闭的终端混在一起；终端一多，Tasks 和 Changes 也会被挤进溢出菜单。
- **Changes 和 Terminal 做成主区的标签页**，像编辑器那样和聊天切换或分栏：聊天是主体，右侧面板的价值就是一边看对话一边看改动或终端。
- **终端按目录归属**（同一项目目录下的家族共用一组终端）：切到别的对话会看到别的任务开的终端，收尾时机也不清楚——没有哪一条对话的归档能代表这个目录"用完了"。
- **把 Overview 收进面板，合成一个 Inspector**：用户希望保留轻量浮层，只想扫一眼时不用打开面板。

## 后果

- 只改 `apps/web`，桌面端随之继承；iOS 不变（M7 已经把概览收进 sheet，手机上侧重看对话）。
- Tasks 和 Changes 不改协议。Terminal 要新增调用和流，只加不改，`PROTOCOL` 升小版本；宿主多了一个 pty 原生依赖，npm 单包（ADR-0016）要带上各平台的预编译产物。这些在 #547 里定。
- 终端是一个新的交互入口：任何配对过的设备都能经中继在宿主上开 shell。agent 本来就能跑 bash，权限没有变大，但是否按设备限制（#502）在 #547 里决定。
- 头部宽度随面板拖动变化，标题照旧截断。
- 实现按 M11 的 issue 分步：#545 容器和 Tasks，#546 Changes，#547 宿主终端和协议，#548 Terminal 页。
