# ADR-0026：运行过程在对话里收成一行，正文只留说给用户的话

- 状态：Accepted
- 日期：2026-10-20
- 修订 ADR-0014 §2 对思维链组件的约定：这部分不再和 Pace 保持同形

## 背景

Web 的思维链组件是按 ADR-0014 从 Pace 原样搬来的（Pace ADR-0030）：运行中把每一步平铺出来、强制展开，运行结束才收成「Worked for …」。iOS 的 AgentChatKit 做法相近：思考和执行阶段自动展开，开始回答才收起。步骤数量没有上限。

实测（#214，omarchy 宿主数据，对话 378）：22 次工具调用的运行平铺出 27 行，Web 在 1280×900 下高 917px，iPhone 一屏放不下；59 次调用的运行有 78 行。这些行是「Ran 2 commands」「Thought」这类摘要，信息量很低。同一批运行里插话数都是 0，思考块都不为空，todo 只在 59 次调用的那次里写过两次（开头一次、结尾一次）。

用户的判断：对 agent 越信任，越只关心结果，trace 的需求越低；模型越快，一次回答里的工具和思考循环越多。trace 留在对话里显然不合理。想看过程细节的开发者有遥测工具和完整的轨迹可用。

## 决策

1. **正文只放说给用户的话和要用户操作的东西**：回答、插话、提问卡片、子代理卡片。工具调用和思考在对话里收成一行，用户不点就不展开，运行中也一样。去掉"运行中强制展开"和"按阶段自动展开"。
2. **Web / 桌面按插话分段**：插话是正文；两段插话之间的工具调用和思考收成一行灰色摘要（动词总结，带 diff 统计和失败数），点开在原地列出这一段的步骤。模型不插话时，整次运行就是一行。不开右侧面板：过程属于对话，不该让用户换地方看。
3. **iOS 每次运行一颗胶囊**：运行中标签是最近一条插话的首行，没有插话时是当前动作；点开从底部弹 sheet，里面按时间顺序排插话和步骤。插话不进正文：进了正文就收不回一行，而手机上用户更在乎结果。
4. **todo 跟在最新一次运行后面**：永远是这次运行的最后一个元素，随对话滚动，只在这次运行写过 todo、或者还有没完成的项时出现，界面上同时只有一张。Web 默认展开成卡片，iOS 在胶囊下面占一行。标出最后一次写 todo 的时间，因为模型可能只在开头和结尾写。
5. **不靠提示词凑内容**：宿主不加引导插话、todo 或最终回答写法的提示词，框架提示词保持简单；`bash` 不加 `description` 参数。界面要在模型不插话、不写 todo 时也成立。
6. **只改展示层**：推导层的步骤列表（含插话）不变，分段在各端展示层做。两端都要的 todo 元数据（这次运行最后一次 `todo_write` 的时间）进推导层，同步改 `crates/pinomad-core`。

## 考虑过的方案

- **运行中只显示最近 N 步，更早的收成一行**：高度有上限，但"+12 steps"看不出做了什么，每来一步窗口都在跳；trace 仍然占着对话。
- **按"一段思考加随后的工具"分轮、用思考首句当标题**：行数减半（27 → 12），但 68 行的运行折完还有 31 行，只是提高了密度，没有把过程移出正文。
- **iOS 也按插话分段，每段一颗胶囊**：和 Web 一致，但插话进了正文就收不回一行，和"手机上只看结果"冲突。
- **Web 用右侧面板看过程**：宽屏有空间，但过程本来是对话的一部分，换地方看是多余的切换。
- **宿主加提示词，要求模型边做边汇报、长任务先写 todo**：插话和 todo 会更多，但 PiNomad 是框架，额外的引导会限制模型发挥；好的模型本来就会这么做。叙述提醒以后可以做成可选的扩展。

## 后果

- 不插话的模型（实测的 deepseek-flash 就是）在 Web 上每次运行只剩一行灰字、在 iOS 上只剩一颗胶囊；运行中能看到的进度只有当前动作和耗时。
- iOS 上插话结束后只在 sheet 里：插话里有、最终回答没重复的信息，用户不点开就看不到。
- todo 可能过期（写完计划就不再更新），界面只标出更新时间，不去猜进度。
- Web 的思维链组件和 Pace 分叉，以后从 Pace 同步改进时这部分不再照搬。
- iOS 要先让 FFI 快照带上 todo（现在只带提问）。
