# ADR-0003：以 coding 为核心，自托管宿主加远程客户端

- 状态：Accepted
- 日期：2026-10-04

## 背景

PiNomad 是 coding 产品，agent 需要真实的 shell、文件系统和代码仓库。Cloudflare 的 PiHarness 能托管对话和任务，但 Workers 里没有可用的 `child_process`，文件系统也是虚拟的。要在云端执行代码，只能另外配沙箱或容器。实际上"serverless"最后也是落在某台具体的服务器上。

## 决策

1. **宿主**是一台具体的机器，比如个人的 Mac mini，或者装了 Linux 的 VPS。宿主运行 Harness、独占 Durable 存储，并直接用本机的 shell 和代码仓库作为执行环境。
2. 桌面、Web、移动端都是**客户端**：只通过网络协议观察和操作宿主，不持有执行状态。桌面端和宿主装在同一台机器上，也按客户端对待。
3. Serverless 托管推迟。`spikes/durable-cloudflare` 只作为未来"云端宿主"形态的证据，不是近期目标。

## 后果

- 宿主和客户端之间需要一套正式协议，客户端只能通过这套协议访问宿主。
- 实验只验证过本机回环地址。远程访问时客户端怎么认证、连接怎么加密、权限怎么控制，都还没有决定（候选：Tailscale、SSH 隧道、自带认证），需要在第一次远程连接落地前另写 ADR。
- 宿主的生命周期（谁启动、怎么常驻、崩溃后谁拉起、怎么升级）需要另外决定。
- 产品里的会话、代码项目、执行检出（worktree）和 Durable 对话之间怎么对应，还没有决定。
