# ADR-0041：终端由宿主在内存里运行，输出按位置回放

- 状态：Accepted
- 日期：2026-11-03
- 补充：ADR-0040 §5（终端的归属和数量）

## 背景

ADR-0040 定了终端归谁、能开几个、在界面上怎么切换，没有定宿主怎么运行终端、输出怎么送到客户端。宿主是 Node 进程，可能作为服务常驻（ADR-0009）；客户端经回环、局域网、中继或 P2P 连接（ADR-0033），会断线，同一个终端可能同时在几台设备上开着。协议里原有的流都是"快照 + chord ops"，没有字节流；所有帧在一条连接上排队，没有优先级。

## 决策

1. **pty 用 `@lydell/node-pty`，懒加载。** 它和 `node-pty` 是同一份代码，按平台拆成独立的包（macOS、Linux 的 x64 和 arm64），npm 安装时按 `optionalDependencies` 只装本机的那个，和 `node-datachannel` 一样。`node-pty` 1.1.0 没有 Linux 的预编译产物，在没有编译器的机器上 `npm i -g` 会失败。加载失败时宿主照常运行：`hello` 里不带 `terminals`，日志里说缺的是哪个包；`apps/cli/smoke.ts` 从装好的包里起一次 pty。
2. **终端只在宿主内存里。** 客户端断线时终端继续运行；宿主停止（`host.close()`、服务停止）时给所有 shell 发 SIGHUP，重启后列表是空的。根对话归档时关掉这个家族的全部终端，包括旧 Fork 的。
3. **输出进每个终端一个有上限的缓冲（512 KiB），每个观看者从自己的位置读。** `seq` 是输出流的位置（UTF-16 码元），永不归零。宿主把 pty 输出攒 8 ms 或 16 KiB 再发；一个观看者上一帧交给传输层后才发下一帧，所以一条对话帧前面最多排着一块终端输出。观看者跟不上时不暂停 pty，也不拖慢别的观看者：它的位置掉出缓冲后，下一帧是整个缓冲，带 `reset`。订阅带 `since`：缓冲里还有就接着发，没有就整个重发。重启终端时缓冲清空、`seq` 继续往前，所有观看者从新 shell 的第一段输出开始。
4. **协议是新的流和帧，不是 chord ops。** 列表走 `terminals:<conversationId>`（快照，每次变化重发），输出走 `terminal:<id>`，帧类型是 `output`。旧客户端不订阅这两种流，也就收不到新帧；收到也会按 ADR-0018 忽略。
5. **多台设备都能看、都能输入，尺寸跟着最近一次输入或改尺寸的设备。** 宿主记住每条连接对每个终端最后报的尺寸，这条连接输入时把 pty 调到它的尺寸；列表里带当前尺寸，别的设备据此显示。
6. **不按设备限制谁能开终端。** 配对过的设备本来就能让 agent 跑 `bash`，终端没有多给权限，只是多了一个交互入口。按设备的权限（含"不能开终端"）留在 #502。
7. **终端 id 是随机 UUID，`Terminal N` 是每个所有者单独计数的序号。** 没有按设备的隔离，id 不能是能顺着猜的计数；关掉一个终端不会让后面的改名。

## 考虑过的方案

- **在宿主上用 tmux 运行每个终端**，客户端经 tmux control mode 连：宿主重启后终端还在，重连时 `capture-pane` 给出准确的屏幕，也不要原生模块。但 macOS 不自带 tmux，终端能不能用取决于宿主装了什么；control mode 的解析本身是一个不小的项目。
- **宿主上用 `@xterm/headless` 保存屏幕状态**，重连时发序列化的屏幕而不是原始输出：全屏程序（`vim`、`top`）在长时间断线后也能正确显示。代价是宿主要解析所有输出。协议不用改（`reset` 的内容本来就是"能还原当前屏幕的终端数据"），需要时再换。
- **原始 `node-pty`**：Linux 上要现场编译，见决策 1。
- **按键作为不需要回复的新客户端帧**：省一次回复，但没有出错的回路（终端已关、id 不对）。按键仍是调用，只是客户端不让它排在会改状态的调用后面。

## 后果

- 宿主多了一个原生依赖。`@lydell/node-pty` 目前只有 beta 版本，锁精确版本，升级时看 smoke 和 Linux 上的实测。
- 长时间断线后，缓冲的开头可能切在全屏程序的初始化序列之后，`vim` 之类要按一次 Ctrl-L 重画。
- 宿主重启会丢掉所有终端和其中运行的进程，界面上要说清楚。
- iOS 不打开终端；Rust 核心只同步了调用名和门控（`PROTOCOL` 5.27），没有 FFI。
