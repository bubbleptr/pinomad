# ADR-0035：客户端同时连接多台宿主

- 状态：Accepted
- 日期：2026-10-29
- 补充 ADR-0007（在"项目 → 对话"之上加一层宿主分组）和 ADR-0022 §8（客户端汇总多宿主）；修订 ADR-0022 §6（不再广播"新设备通过账号加入"）

## 背景

ADR-0022 §8 定下"多宿主由客户端汇总，每个对话只属于一台宿主，宿主之间不同步"，并把"客户端同时连多台宿主"留到后续阶段。此前各端都按单宿主实现：客户端任意时刻只维护一条宿主连接，切换宿主在 Web 上靠改 `activeHost` 并整页刷新，在 iOS 上靠关闭旧会话再建新会话；点开另一台宿主的推送也会断开当前连接。

实际使用中，一个账号下常有多台宿主同时跑任务（例如桌面开发机和常开的 Linux 机器）。单连接模型有三个直接问题：

- 切走后看不到其他宿主的对话列表更新，Web 端也收不到后台宿主的运行完成通知。
- 跨宿主切换要拆掉重连，正在发送的消息、分块上传的附件和取图请求都会被打断。
- 账号下新加入的宿主需要用户逐台手动点"加入"，而被吊销或主动忘记的宿主缺少明确的自动登记边界。

底层会话本来就是按宿主隔离的：每个客户端会话自带候选和 P2P 协调器（ADR-0032、0033），Rust 核心没有进程级状态，ADR-0024 §3 的保序契约也按单条会话成立。需要定下来的是客户端上层的对话标识、连接与订阅生命周期、状态归属、机器三维状态、自动登记规则以及通知行为。

## 决策

1. **全局对话引用与按宿主分组的列表。** 客户端内部凡是跨宿主可见的地方，对话一律用 `ConversationRef = { hostKey, conversationId }` 标识：iOS 的路由、按对话保存的输入状态、Web 聊天树的组件挂载键、运行通知的去重标识和点击目标、推送打开目标。宿主内部和线上协议仍然是裸 `conversationId`。客户端在 ADR-0007 的"项目 → 对话"上面加一层宿主，侧栏严格按已配对宿主的存储顺序分组，不做跨宿主的"最近"混排视图或跨宿主搜索。Web 不加对话 URL 路由，只把原来的活跃宿主记录改为记住上次聚焦的 `ConversationRef`（没有对话时只记 `hostKey`），仅用于加载时恢复。

2. **每台已配对宿主一条连接，单一聚焦，失焦即释放对话订阅。** Web 和桌面端在页面打开期间连接所有已配对宿主；iOS 在前台连接所有已配对宿主，后台靠 APNs（进出后台时对所有会话扇出前后台通知，不另外主动断开后台连接）；网络变化事件同样扇出给所有连接。每条连接各自重连、退避，各自持有候选和 P2P 协调器，个人使用场景下不设连接数上限。全客户端任意时刻只有一个聚焦的 `ConversationRef`，由屏幕上当前显示的对话决定。打开另一台宿主的对话时，目标连接订阅该对话，**原连接立即释放主对话和侧对话的订阅**，只保留宿主级流（对话列表、设备、设置、Providers、MCP 等），非聚焦宿主不收对话流，宿主也不为它维护对话 watch。为此在 TS 控制器和 Rust 核心（含 FFI）上公开"清空当前对话"接口，包装现有的私有取消订阅逻辑；线上协议已有 `unsubscribe`，不改线上协议、不升 `PROTOCOL`。释放对话订阅不得中断未结算的连接级操作：提交恢复对账（ADR-0034，按 `requestId` 查询）、附件分块上传和按引用取图都绑在连接上，切换聚焦后在原连接上继续完成；iOS 后台附件上传只承诺尽力继续，挂起后回到前台按现有偏移恢复或重试。忘记宿主直接关闭并移除那条连接，不再重新加载页面。

3. **每台宿主一个完整运行时，状态按宿主或 `ConversationRef` 隔离。** 每台宿主拥有独立的客户端运行时，持有自己的会话、宿主视图快照、技能与命令缓存、流式回复缓冲、会话代际（generation）、连接尝试和在途标记；屏幕上渲染什么只由聚焦的 `ConversationRef` 决定。非聚焦宿主的快照更新不得改动聚焦对话的回复流，迟到的异步结果按各自宿主的代际判断。各状态的归属边界固定如下：
   - **按 `ConversationRef` 隔离**：消息草稿、附件托盘、排队编辑、问题回答草稿、已选 skill 标签。
   - **按 `hostKey` 隔离**：新对话草稿（含所选项目、执行检出、具名 Agent 和附件）、新对话的默认模型选择、侧栏项目展开状态（`hostKey` + 项目路径）、Web 的协议重载标记。
   - **图片字节共用、在途请求按来源分开**：已取回的图片字节按 `ref + variant` 全局共用（`ref` 是内容 sha256，ADR-0027）；在途取图请求按 `hostKey + ref + variant` 区分，一台宿主取图失败或卡住不连累另一台，失败后可换当前有效的来源宿主重取。
   - **诊断与提示归属宿主**：iOS 的提示、性能日志（PerfLog）和 signpost 带上来源宿主标识。

4. **机器状态拆成信任、连接、登记进度三个维度。** 不用单一枚举混装所有状态，拆成三个维度并在界面上合成为一句状态文案：
   - **信任**（持久，按 `hostKey` 或账号 `hostId`）：`paired`、`unpaired`（账号名下有、本机未登记）、`revoked`（收到过已认证的 4401，**保留本地身份记录**不删除）、`keyChanged`、`declined`（不自动登记）。
   - **连接**（仅对 `paired`）：`connecting`、`connected`、`offline`（曾经连上过又断开，展示内存里最后一次列表并置灰只读，后台继续重连，列表不落盘）、`terminal(reason)`（不再自动重试，覆盖协议主版本不兼容、4400 等终止关闭码、4401，文案按原因区分）。
   - **登记进度**（仅对 `unpaired`，内存）：`idle`、`pairing`、`saveFailed`（Noise 握手成功、宿主已登记，但本地保存失败）。

5. **账号宿主的自动登记规则。** 账号刷新（启动、登录、回到前台）时，客户端对符合资格的账号宿主逐台经服务端担保自动登记（ADR-0022 §4），用户不再手动点"加入"；自动登记成功不改变当前聚焦，单轮失败不立即重试。
   - **资格**：信任维度是 `unpaired`，不在 `declined` 集合中，且本地已配对宿主列表**读取成功**。本地列表读取失败时一律不自动登记，不能把读取失败当成空列表；`keyChanged` 和 `revoked` 永不自动登记。
   - **`declined` 持久集合**：按 `(服务端 origin, hostId)` 持久化。用户忘记一台账号宿主，或宿主拒绝账号担保（关了"接受账号担保的设备"）时写入；只有用户在这台设备上显式点"加入"才移除，防止被吊销或主动忘记的宿主在下次刷新时被自动加回。
   - **单飞与跨标签页锁**：按 `hostId` 单飞，同一客户端内刷新重入只跑一份；Web 多标签页用 Web Locks（`navigator.locks`，键带 `hostId`）互斥，拿到锁后重新读本地已配对列表核对资格再执行。退出账号或忘记宿主时作废在途登记任务。
   - **保存失败只重试保存**：握手成功但本地保存失败（`saveFailed`）时，在按 `hostId` 分开的恢复槽里保留这把设备身份，后续只重试本地保存，不再生成新密钥、不重复向宿主登记。

6. **不再广播"新设备通过账号加入"（修订 ADR-0022 §6）。** 宿主删掉设备经账号担保登记时的全员 `info` 广播；新设备只在宿主的 Devices 列表里实时出现，并照旧标出来源为"账号"。代价是服务端被攻破并替攻击者担保新设备时，在线设备不再收到即时提示，只能从设备列表里看出来；在个人自部署场景下接受这个取舍。

7. **新对话选宿主，切换宿主不迁移草稿。** 每台宿主分组上有自己的"新对话"入口；全局"新对话"默认用上次新建对话所在的宿主，那台宿主不在线时回落到第一台在线宿主（回落只在打开空白新草稿时发生）。在草稿页切换宿主，直接切到目标宿主自己的新对话草稿，不迁移文字、附件、项目或具名 Agent：这些都是宿主本地资源，即使两台宿主有同名项目或同名 Agent 也互不相通。

8. **共享层只放两项纯规则，不建跨语言的机器名册。** 列表分组、宿主运行时表和三维状态合成留在各端的组合根（TS / Swift），跟随各端自己的生命周期。进入 `packages/client` 和 `crates/pinomad-core`（并用对照向量对齐）的只有两端必须一致的两项：控制接口的"清空当前对话"，以及自动登记资格纯函数（给 `matchAccountHosts` 补上 `declined` 集合和"本地列表是否读取成功"两个输入，输出每台账号宿主是否可自动登记）。

9. **通知只压制当前可见对话，iOS 推送登记在所有时机扇出。**
   - **通知压制**：两端统一只压制当前屏幕上正显示的那个 `ConversationRef` 的通知；即使窗口或应用在前台，只要看的是别的对话（不管在同一台宿主还是另一台宿主），照常发通知。Web 改掉原来"窗口在前台就全压"的规则，通知监听挂在宿主运行时上，切换聚焦不重置基线。
   - **iOS 推送登记与打开**：在会话 ready、重连、回前台、APNs token 更新、通知权限或开关变化时，都对所有已连接会话同步推送登记；忘记宿主前照 ADR-0025 §9 先清除登记。点开推送时，目标宿主已配对就直接打开该 `ConversationRef`，那条连接未就绪就等它 ready，不断开其他宿主的连接；未配对则丢弃。

## 考虑过的方案

- **失焦后继续挂着旧宿主的对话订阅**：初稿认为不改线上协议就只能让旧连接继续持有上一条对话的订阅。批评轮指出协议已有 `unsubscribe`，客户端核心也有现成的私有 `#unshow` / `unshow()`，只需在控制器上公开方法就能在失焦时释放主对话和侧对话订阅。挂着旧对话既浪费带宽和宿主 watch，又没有必要。
- **在共享层建跨语言的完整机器名册**：把宿主列表、三维状态、连接调度和分组排序全收进 `packages/client` 与 `crates/pinomad-core`。这会把 Web Locks、钥匙串读写、UI 分组生命周期塞进无 I/O 的核心层，增加 FFI 表面积却不减少平台层代码。缩减为只共享"清空当前对话"和"自动登记资格"两项纯规则。
- **保留登记时向其他设备广播（ADR-0022 §6 原方案）**：能在服务端被攻破、私自担保设备时给在线设备即时提示；但多宿主自动登记下，每登录一台新客户端都会在所有在线设备上连弹多条广播。用户决定去掉广播，只留设备列表里的来源标记。
- **收到 4401 删除本地宿主记录，或忘记宿主不记 `declined`**：删掉记录会丢失 `revoked` 上下文，客户端下次刷新账号会把它当成未配对宿主重新自动登记；忘记账号宿主若不记入 `declined`，同样会在下次刷新时被自动加回。因此 4401 保留本地记录并标为 `revoked`，主动忘记或宿主拒绝担保写入持久的 `declined` 集合。
- **图片在途请求也跨宿主共用**：图片字节按内容哈希寻址，到手后可以全局共用；但如果在途请求也按 `ref + variant` 全局合并，一台宿主的请求超时或断线就会拖住另一台宿主的同一张图。改为字节共用、在途请求按来源宿主分开。
- **草稿页换宿主时迁移草稿内容**：已上传的附件在原宿主磁盘上，项目路径、执行检出和具名 Agent 也是原宿主的本地对象，跨宿主搬过去无法成立。改为每台宿主各自持有一份新对话草稿。

## 后果

- ADR-0007 的"项目 → 对话"层级之上增加一层宿主分组；ADR-0022 §8 的多宿主汇总落地，§6 的账号设备加入广播被移除。
- 线上协议不改，`PROTOCOL` 不升版本；`packages/protocol`、`packages/client` 和 `crates/pinomad-core` 同步增加清空当前对话方法与自动登记资格输入，并更新对照向量。
- 客户端同时维护所有已配对宿主的连接与各自的 P2P 协调器，但任意时刻只有一条聚焦对话持有对话级流订阅；非聚焦连接只收宿主级流。
- 宿主离线时客户端只显示当前进程内存里最后一份列表（置灰只读），不把对话列表持久化到客户端磁盘；冷启动时离线宿主只显示机器状态。
- 服务端被攻破并私自担保新设备时，在线客户端不再收到实时广播提示，只能从宿主的 Devices 列表中排查。
