# ADR-0049：开放插件：插件可以自带界面代码，只在 Web 和桌面端

- 状态：Accepted
- 日期：2026-11-12
- 修订：ADR-0004 §4（插件可以自带界面代码）、§5 和后果（开放的条件和先后顺序）；ADR-0005 中"插件状态只经展示类型呈现"的前提（展示类型留给内置扩展继续用）

## 背景

ADR-0004 写于第一个真实需求出现之前，那时假设插件只需要暴露数据，界面一律由 PiNomad 按展示类型渲染，并为开放协议定了三个条件。

第一个真实需求是 artifact：模型写出一个页面，在侧边面板里看、和它交互。这是任意界面，不是几种固定的结构化数据：

- MCP 只有工具和资源，没有界面；
- 展示类型（ADR-0005）是有限的一组 schema，表达不了任意界面，第 3 层的声明式视图树也只是受限的组件树。

"三个客户端用同一套设计系统渲染"和"插件自带任意界面"互相冲突：插件作者不可能同时写 React 和 SwiftUI。这里的取舍是 iOS 不对插件界面做承诺。

## 决策

1. **插件不只是模型工具**：可以带自己的界面代码，以后还可以做编排。第一个用例是 artifact 插件，只作为示例提供，默认不启用。
2. **插件的界面代码和 Web 外壳加载在同一个页面里，装即信任。** 接受的风险：插件代码能读到这个页面保存的设备密钥。模型写出的内容（如 artifact 的 HTML）仍放进外壳提供的沙箱里，不和外壳同页。
3. **插件界面是 Web 和桌面端的能力**，iOS 不承诺：插件的工具在 iOS 上照常可用，只是没有插件界面。插件不再要求各端渲染一致。
4. **插件按 PiNomad 自己带版本号的插件 API 写**，不直接用 chord 的 API（上游 Chord v2 正在重写）。文件形状照 chord：一个宿主侧文件、一个浏览器侧文件。
5. **插件只经具名插槽贡献界面**，不碰外壳的 DOM。第一版的插槽：侧边面板里的一个 Surface，按工具名注册的工具卡片。
6. **第一版的安装方式**：本地目录 `<dataDir>/plugins/<name>/`（默认 `~/.pinomad/plugins/<name>/`），里面的 `plugin.json` 是 `{ "name", "api": 1, "host": "host.ts", "web": "web.js" }`；宿主启动时加载，改了要重启。不做项目级插件、npm 或 git 安装、插件市场。浏览器侧的 `web.js` 由插件作者自己构建；`host.ts` 直接靠 Node 的类型剥离运行。
7. **第一版的范围**：插件工具、按对话的状态（Durable 文档，`shared: false` 的状态只留在宿主）、界面可以调用的宿主方法、侧边面板和工具卡片。编排（钩子、创建对话、定时任务、插件命令）以后再做。
8. **API 形状**（名字是提议）：宿主侧 `tool`、`state`、`method`；浏览器侧 `panel`、`toolCard`、`useState`、`useCall`、`openPanel`、`Sandbox`。API 对象作为参数传给插件的默认导出，插件只 import 类型。
9. **工具卡片拿到工具名、参数和输出文本，不拿 `details`**，所以客户端推导层的 Rust 镜像不用改。

## 后果

- 宿主提供的页面、服务端提供的页面和桌面端页面的 CSP `script-src` 都要加上 `blob:`，用来加载插件的浏览器侧代码。
- 协议加两样：hello 里的插件列表（名字、API 版本、浏览器侧代码的哈希和大小），以及两个调用：取浏览器侧代码、调用插件的宿主方法。
- 设备密钥暴露给插件代码，这是装即信任的代价；只装自己信得过的插件。
- 以后如果桌面端换成原生外壳，插槽要放在 WebView 里。
- 落地页"rendered the same way in the web, Mac, and iPhone clients"这句对插件不再成立，由后面的 PR 改。

## 没选的方案

- **只有数据的插件（ADR-0004 的路线）**：插件只出结构化数据，界面由 PiNomad 渲染。满足不了 artifact 这类任意界面。
- **隔离的 iframe 加消息桥**：插件界面跑在独立源的 iframe 里，经 postMessage 调外壳。安全边界更好，但每个插槽都要一层桥接、尺寸同步和主题同步，第一版的成本过高；模型写的内容仍然走沙箱。
- **直接把 chord 暴露给插件**：Chord v2 在重写，直接暴露等于把上游的破坏性变更转嫁给插件作者。
- **宿主构建浏览器侧代码**：宿主要带打包器，构建失败也要在宿主上排查；由插件作者构建，宿主只读文件。
- **把 artifact 做成内置扩展**：解决了眼前的需求，但插件机制仍然没有第一个用户来验证。
